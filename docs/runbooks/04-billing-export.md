# Runbook 04. Биллинг-выгрузка прошла не полностью

Когда: прогон утверждён, но часть оснований осталась в статусе «Выгружается» или «Выгружен с ошибками» ([02 §4.9](../02-functional-spec.md)).

Роли: **Finance** (повтор выгрузки), **Admin CRM** (очередь и журналы).

## 1. Понять масштаб
Экран прогона показывает счётчики и список оснований с причиной отказа. Те же данные в API:
```
GET /api/v1/billing/runs/{id}
GET /api/v1/billing/runs/{id}/bases?status=ExportFailed
```
Очередь исходящих операций и последние ошибки — «Администрирование → Интеграции» и `GET /api/v1/integrations/runs?system=poweroffice`.

## 2. Частые причины
| Что в сообщении | Что делать |
|---|---|
| `The customer is not linked to a PowerOffice customer` | Связать клиента на экране «Сопоставления» и повторить выгрузку основания |
| `Product … has no PowerOffice code` | Заполнить код продукта в каталоге (BR-CAT-05), повторить |
| 401/403 от PowerOffice | **Runbook 02 §4** — ротация Application Key; до неё поставьте интеграцию на паузу (**runbook 05**) |
| 429 или таймауты до отправки | Ничего не делать: очередь повторяет с возрастающей паузой. Проверить через час |
| `Sales order already exists` / `Order … already existed` | Ключ `{период}-{клиент}-{прогон}` нашёл заказ: основание помечается выгруженным, дубля нет |
| Основание «Требуется сверка», `An earlier send got no answer…` | Отправка ушла и осталась без ответа, а заказ по ссылке не найден. CRM второй раз **не** отправляет — см. §3a |

## 3. Повторная выгрузка
1. Исправьте причину.
2. На основании — «Выгрузить снова» (или `POST /api/v1/billing/bases/{id}/export`).
3. Повтор идемпотентен (BR-BIL-05): существующий заказ находится по внешней ссылке, второй заказ не создаётся.

## 3a. Сверка неизвестного результата (ADR-013)
1. В PowerOffice найдите заказ клиента за период (внешняя ссылка — ключ основания из журнала попыток).
2. На основании — «Сверить» (`POST /api/v1/billing/bases/{id}/reconcile`, If-Match): «Заказ есть» с номером — основание выгружено, начисления выставлены; «Заказа нет» с причиной — основание «Ошибка», его можно отправить снова или отменить.
3. Пока основание не сверено, его нельзя отменить (`BIL_RECONCILE_FIRST`): иначе следующий прогон выставил бы его второй раз.

## 4. Если выгрузка невозможна сегодня
- Основание можно **отменить** (`/cancel` с причиной, If-Match), пока отправка не начиналась; его начисления освобождаются, и дополнительный прогон периода выставит их снова. Если счёт клиенту выставлен вручную, не отменяйте — «Указать заказ, созданный вручную» (§4 runbook 07).
- Если счёт уже создан в PowerOffice, отмена запрещена: кредит-нота оформляется в PowerOffice, а корректировка попадает в следующий прогон (BR-BIL-09).
- Когда PowerOffice недоступен дольше рабочего дня — **runbook 07** (ручной биллинг).

## 5. Закрытие
- Прогон закрывают только когда все основания выгружены или отменены.
- Второй обычный прогон закрытого месяца не создаётся (`BIL_PERIOD_ALREADY_BILLED`). Поздние часы и позиции выставляет **дополнительный** прогон (переключатель в диалоге «Новый прогон»): он берёт только то, чего не держит реестр начислений.
- Часы получают статус «Выставлена» автоматически после выгрузки (BR-BIL-08); если статус не изменился, проверьте outbox (`/api/v1/integrations/runs?system=poweroffice`) — событие доставляется через очередь и может отставать на минуты.
