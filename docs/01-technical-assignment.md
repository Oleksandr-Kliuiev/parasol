## 1. Общие сведения

**Наименование системы:** Vardahei CRM v2 (далее — «CRM», «Система»).

**Заказчик:** IT-компания — поставщик услуг, лицензий и поддержки продуктов Microsoft, Atera и PowerOffice (далее — «Компания»).

**Основание для разработки:** замена разрозненного учёта (таблицы, заметки, ручная сверка между Atera, PowerOffice и Partner Center) единой системой управления клиентами, продажами, контрактами и биллингом.

**Плановые сроки:** Этап 0 (обследование и PoC интеграций) — 3 недели; Релиз 1 (MVP) — ~4 месяца; Релизы 2–3 — по плану в [08-roadmap](08-roadmap.md).

## 2. Назначение и цели

### 2.1 Назначение
CRM — единое рабочее место сотрудников Компании для работы с клиентом на всём жизненном цикле: лид → сделка → предложение → контракт → оказание услуг и поставка лицензий → ежемесячный счёт → продление/допродажа.

### 2.2 Бизнес-цели и измеримые показатели

| ID | Цель | Показатель успеха (через 3 мес. после запуска R1) |
|----|------|------|
| G-1 | Не терять выручку при биллинге | 100 % оплачиваемых часов из Atera и активных CSP-подписок попадают в счёт; ручная сверка ≤ 1 рабочего дня в месяц (сейчас — оценить на Этапе 0) |
| G-2 | Ускорить ежемесячный цикл выставления счетов | Биллинг-прогон от закрытия периода до отправки в PowerOffice ≤ 2 рабочих дней |
| G-3 | Видеть клиента целиком | Карточка 360° открывается ≤ 2 с и показывает контакты, контракты, лицензии, тикеты, устройства, счета и задолженность |
| G-4 | Не пропускать продления и окна отмены | 0 пропущенных продлений CSP-подписок и контрактов; уведомления за 60/30/7 дней |
| G-5 | Управляемые продажи | Все сделки в воронке, прогноз выручки по месяцам, конверсия по этапам |
| G-6 | Безопасность и соответствие | Вход только через Entra ID с MFA; полный аудит изменений; соответствие GDPR |

## 3. Характеристика объекта автоматизации

### 3.1 Направления бизнеса Компании
1. **Microsoft** — перепродажа лицензий (CSP: Microsoft 365, Azure, Dynamics и др.), внедрение и миграции, администрирование тенантов клиентов, поддержка.
2. **Atera** — managed services (MSP): мониторинг и обслуживание устройств клиентов через Atera RMM, сервис-деск, абонентское обслуживание (за пользователя / устройство / пакет часов).
3. **PowerOffice** — внедрение PowerOffice Go у клиентов, обучение, поддержка, интеграции.

### 3.2 Внутренний системный ландшафт Компании

| Система | Использование Компанией | Роль для CRM |
|---|---|---|
| Microsoft Entra ID | Учётные записи сотрудников, MFA, Conditional Access | Провайдер идентификации, роли через группы |
| Microsoft 365 (Outlook, Teams, SharePoint) | Почта, календарь, чаты, документы | Привязка писем и встреч к клиентам, уведомления, хранение документов |
| Microsoft Partner Center (CSP) + GDAP | Продажа лицензий, доступ к тенантам клиентов | Источник подписок, цен, биллинговых данных; данные об использовании лицензий |
| Atera | Тикеты, RMM, учёт времени техников | Источник тикетов, устройств, алертов и оплачиваемых часов |
| PowerOffice Go | Бухгалтерия, счета, дебиторка | Получатель заказов для выставления счетов; источник статусов оплаты |
| Brønnøysundregistrene (Enhetsregisteret) | Публичный реестр компаний Норвегии | Автозаполнение реквизитов клиента по оргномеру |

### 3.3 Проблемы текущего процесса (подтвердить на Этапе 0)
- Данные о клиенте разнесены по 4+ системам, нет единой карточки.
- Счета собираются вручную: часы из Atera, лицензии из Partner Center/от дистрибьютора, абонплата из договоров.
- Сроки продления контрактов и NCE-подписок отслеживаются вручную.
- Нет прозрачной воронки продаж и прогноза выручки.
- Нет единого аудита «кто что изменил».

## 4. Границы системы

### 4.1 Входит в объём
- Клиенты (организации), контакты, карточка клиента 360°, обогащение из Brreg.
- Продажи: лиды, сделки, воронка, коммерческие предложения (PDF), каталог продуктов и прайс-листы.
- Контракты и SLA: абонентские услуги, пакеты часов, продления, индексация цен.
- Лицензии Microsoft: синхронизация CSP-подписок, контроль продлений, сравнение «куплено / используется» (через GDAP).
- Сервис: зеркало тикетов, устройств и алертов из Atera; создание тикета из CRM.
- Учёт времени: импорт часов из Atera, ручной учёт в CRM (проекты), согласование.
- Биллинг: ежемесячный прогон, основание для счёта, выгрузка в PowerOffice, обратная синхронизация счетов и оплат.
- Проекты внедрения (упрощённо): этапы, задачи, бюджет часов.
- Активности: задачи, звонки, заметки, встречи и письма (Outlook), уведомления в Teams.
- Документы клиента в SharePoint.
- Отчёты и дашборды; доступ Power BI к витрине данных.
- Администрирование: пользователи и роли, настройки интеграций, журнал синхронизаций, аудит.

### 4.2 Не входит в объём (явно)
- Замена сервис-деска Atera (тикеты ведутся в Atera; CRM показывает и создаёт).
- Замена бухгалтерии PowerOffice (счета, НДС/MVA, EHF, напоминания об оплате остаются в PowerOffice).
- Покупка/изменение CSP-подписок из CRM в Релизах 1–2 (только чтение; запись — кандидат в Релиз 3).
- Маркетинговые рассылки (при необходимости — интеграция с внешним сервисом позже).
- Нативные мобильные приложения (адаптивный веб/PWA достаточен).
- Клиентский портал — Релиз 3, отдельное согласование.

## 5. Пользователи и роли

Ориентировочно 10–50 внутренних пользователей. Роли назначаются через группы Entra ID (см. [06-security](06-security.md)).

| Роль | Код App Role | Основные задачи |
|---|---|---|
| Администратор | `Crm.Admin` | Настройка системы, интеграций, справочников, ролей |
| Руководство | `Crm.Management` | Все данные на чтение, отчёты, маржинальность, утверждение скидок сверх лимита |
| Менеджер по продажам / аккаунт-менеджер | `Crm.Sales` | Лиды, сделки, предложения, клиенты, контракты, продления |
| Техник / консультант | `Crm.Technician` | Карточка клиента (без финансов), тикеты, устройства, учёт времени, проекты |
| Руководитель сервиса | `Crm.ServiceLead` | Всё, что у техника + согласование часов, SLA-отчёты, загрузка команды |
| Финансы | `Crm.Finance` | Биллинг-прогоны, прайс-листы, себестоимость, выгрузка в PowerOffice, дебиторка |
| Только чтение / аудитор | `Crm.ReadOnly` | Просмотр без финансовых полей, без изменений |

Детальная матрица прав — в [02-functional-spec § 2](02-functional-spec.md#2-роли-и-матрица-доступа).

### 6.4 Требования безопасности (сводно)
- SEC-01 Аутентификация только Entra ID; MFA обеспечивается Conditional Access.
- SEC-02 Токены доступа не попадают в браузер (BFF-паттерн).
- SEC-03 RBAC на уровне API; финансовые поля (себестоимость, маржа) — полевой контроль доступа.
- SEC-04 Секреты интеграций только в Azure Key Vault, доступ по Managed Identity; предпочтение сертификатам перед client secret.
- SEC-05 Аудит всех изменений и доступа к экспорту данных; журнал неизменяем для пользователей, хранится ≥ 5 лет.
- SEC-06 Соответствие OWASP ASVS уровень 2; ежегодный пентест. *(Уточнение DEV-21: базовая версия — ASVS 5.0.0, он заменил 4.0; самооценка выполнена локально, независимая проверка и соответствие не подтверждены — EXT-06, [06-security](06-security.md).)*
- SEC-07 GDPR: реестр обработки, сроки хранения, экспорт и удаление данных субъекта.

Полно — [06-security](06-security.md).

### 6.5 Требования к интерфейсу
- Дизайн-система Fluent UI v9 — привычный сотрудникам вид Microsoft 365, светлая и тёмная тема.
- Навигация: левое меню модулей, глобальный поиск (Ctrl+K), «недавние» записи.
- Списки: фильтры, сохранённые представления, сортировка, массовые действия, экспорт.
- Каждая сущность, синхронизированная извне, показывает источник, время последней синхронизации и ссылку «открыть в Atera/PowerOffice/Admin Center».
- Формат дат `dd.MM.yyyy`, валюта NOK, часовой пояс Europe/Oslo.

### 6.6 Миграция данных
- Источники (подтвердить): CRM v1, Excel-таблицы, клиенты из Atera и PowerOffice.
- Первичная загрузка клиентов — из PowerOffice (финансовый мастер) с сопоставлением клиентов Atera и CSP-клиентов по оргномеру и домену; несопоставленные — в очередь ручного разбора.
- Миграция выполняется повторяемыми скриптами с отчётом о расхождениях; минимум один пробный прогон на staging.

## 8. Порядок контроля и приёмки

1. **Спринтовые демо** каждые 2 недели на staging с данными PowerOffice Demo и тестовым клиентом Atera.
2. **Приёмочное тестирование (UAT)** по сценариям из [02-functional-spec](02-functional-spec.md): каждый сценарий уровня M должен быть пройден.
3. **Параллельный биллинг**: минимум 1 месяц счёт формируется одновременно старым способом и через CRM; расхождение сумм по всем клиентам = 0 NOK или объяснено.
4. **Нефункциональная приёмка**: нагрузочный тест (k6) на целевых объёмах NFR-04, отчёт по сканированию безопасности (OWASP ZAP, Defender for Cloud), проверка восстановления из бэкапа.
5. **Критерии готовности релиза**: нет открытых дефектов критичности Blocker/Critical; ≤ 5 Major с согласованным планом; документация обновлена.

## 10. Глоссарий

| Термин | Значение |
|---|---|
| CSP | Cloud Solution Provider — программа Microsoft для перепродажи облачных лицензий |
| NCE | New Commerce Experience — модель подписок Microsoft (месячные/годовые обязательства, окно отмены 7 дней) |
| GDAP | Granular Delegated Admin Privileges — ограниченный по ролям и сроку доступ партнёра к тенанту клиента |
| Тенант | Экземпляр Microsoft Entra ID / Microsoft 365 клиента |
| RMM | Remote Monitoring & Management — функция Atera для управления устройствами |
| Агент Atera | Программа на устройстве клиента, через которую Atera его мониторит |
| Пакет часов (klippekort) | Предоплаченный объём часов, списываемый по мере работ |
| Биллинг-прогон | Ежемесячная процедура формирования оснований для счетов |
| Основание для счёта | Набор утверждённых позиций по клиенту за период, передаваемый в PowerOffice |
| Оргномер | Organisasjonsnummer — 9-значный номер организации в Enhetsregisteret |
| MVA | Норвежский НДС (стандартная ставка 25 %) |
| MRR / ARR | Ежемесячная / годовая регулярная выручка |
| BFF | Backend-for-Frontend — серверный слой, который держит токены и сессию за SPA |
