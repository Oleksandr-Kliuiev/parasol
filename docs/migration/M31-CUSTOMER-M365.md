# M31 — сохранённый обзор Microsoft 365 в карточке клиента

Локальная разработка на `feat/customer-m365-overview` от M30. Обзор добавлен отдельной
вкладкой в техническую карточку клиента. Его задача — быстро показать, есть ли сохранённые
данные Microsoft 365, насколько они свежие и какие части окна входов не покрыты.
Локальная приёмка завершена полным source-build composition M31 и отдельными строгими
Atlas/CRM наборами. Это не завершение всей продуктовой цели. Рабочие аккаунты, публикация и Hostinger VPS не затрагиваются.

## Поведение

Вкладка загружается при открытии. Показываются количество записей пользователей,
количество облачных регистраций устройств, состояние и даты снимков. Регистрации
Microsoft 365 не складываются с машинами Atera/Atlas и не выдаются за лицензии.
Нулевое количество в опубликованном пустом снимке отличается от отсутствующего
или истёкшего снимка: для последних количество недоступно.

Покрытие входов относится к предыдущим 24 **полным часам UTC**, без текущего неполного
часа. Начало/конец рассчитывает транзакция Atlas по часам БД. Выводятся полный/частичный/
недоступный обход, свежесть и раскрываемые интервалы без покрытия. Это покрытие обхода
источника, не гарантия доставки событий и не заключение о безопасности клиента.

До восьми активных привязанных подключений отображаются в порядке ID; общий итог и
предупреждение явно обозначают неполный список. Нет активного подключения — отдельное
состояние, не «клиент здоров». Отсутствующие данные не заменяются фикстурой или нулём.

Refresh читает сохранённые снимки. Нет вызова Graph, запуска sync, разрешения secretRef,
создания задачи, записи часов или изменения наблюдения. Пользовательские/внешние ID,
имена/UPN/IP, directory DTO, строки событий и тексты upstream ошибок не передаются
в браузер. Доступна только локальная ссылка на подключение Atlas в закрытом disclosure.

## Контракт и доступ

- Atlas: `GET /clients/:clientId/m365/overview`, отдельный `atlas.m365-overview.v1`.
  Старые ClientContext/Stage 2 evidence DTO не расширены. Все query keys отклоняются:
  caller не задаёт tenant, connection, authority, окно или cursor.
- Текущие `context:read` **и** `m365:read` проверяются на одном клиентском membership;
  workspace берётся у actor. Используются обычный guarded read, RepeatableRead, RLS,
  существующие проверки binding и ACTIVE. FIXTURE/DISABLED не становятся evidence.
- Читаются только метаданные поколений и существующая оценка покрытия. Сохраняются
  штатные правила свежести и retention; схемы, триггеры и роли БД не ослаблены.
- CRM: `GET /api/v1/parasol/customers/{id}/m365`, одновременно `customers.read` и
  `parasol.atlas.read`, личные credentials сотрудника. Роль CRM сама не даёт M365 read.
- Общий бюджет reader — 10 секунд; фиксированный source path, максимум 128 КиБ,
  без cookies, redirects, автоматических повторов и HTTP credential logs.
- BFF проверяет закрытую структуру, scope, UTC-даты, count и согласованность покрытия;
  после ответа сравнивает исходную пару **и LinkId**. Изменение связи очищает summary.
- Обе HTTP-границы — no-store. Query key frontend включает сотрудника, permissions
  и клиента; cache lifetime 0, нет автоматического чтения M365 при focus/reconnect.

Синтетический [контракт](../../contracts/customer-m365/README.md) используется в unit
и SQL integration. Frontend имеет независимую BFF-фикстуру и повторно проверяет её
закрытую структуру до показа любых метаданных.

## Отказ в доступе и клавиатура

M365 ACCESS_DENIED или HTTP 403 могут означать отдельное отсутствие `m365:read` либо
полный отзыв токена/контекста Atlas. Поэтому старые счётчики, источники, устройства и
наблюдения скрываются, пока BFF заново читает общий контекст. Другие технические вкладки
на это время недоступны. M365 сообщение и фокус остаются на месте.

Если свежий контекст разрешён, возвращается только новый снимок; M365 остаётся активной
вкладкой с сообщением об отказе, без скрытого повторного M365 GET. Если контекст отказал
или чтение завершилось ошибкой, технические вкладки удаляются, а фокус заранее переводится
на стабильную родительскую кнопку Refresh. Изменение identity по-прежнему инвалидирует
всю техническую карточку. Нельзя сохранять старый Stage 1 snapshot только потому, что
первый отказ пришёл с M365 endpoint.

Интервалы и длинная локальная ссылка используют нативные details/summary. Enter, фокус,
узкий экран 390 px, обе темы и Axe проверяются в настоящих движках; jsdom не подменяет
нативное клавиатурное поведение собственным production key handler.

детерминированную смену LinkId. Browser отдельно проверяет lazy read, смену связи,

нарушений нет. В широком CRM browser наборе новый M365 путь добавляет девять случаев.

Первые diagnostic seeds корректно отклонены PostgreSQL: INSERT начинал с уже потраченным
retry budget, затем STAGING retention превышал 24 часа от startedAt на одну секунду.
Фикстура исправлена через штатный пустой state → charged claim → STAGING → PUBLISHED
с атомарным pointer и допустимым retention. Триггеры не выключались, миграции не менялись.
Эти неудачные запуски очищены и не считаются приёмкой.
