# M20 — версия задачи при завершении и повторном открытии

M19 позволяет точно открыть нужную задачу. Следующий локальный шаг защищает смену её
статуса от устаревшей карточки: сотрудник мог открыть запись раньше, чем коллега изменил
исполнителя, срок или результат. Команда должна относиться к версии, которую сотрудник видел.

## Контракт

`POST /api/v1/activities/{id}/complete` и `/reopen` требуют `If-Match` отображённой Activity.
Нет заголовка — 428 `IF_MATCH_REQUIRED`; неверный формат — 412 `INVALID_ETAG`; устаревшая
версия — 412 `CONCURRENCY_CONFLICT`. Прежние ActivitiesWrite и проверки существования
сохраняются. Отказ не меняет запись, source receipt, audit или outbox.

Сервис проверяет версию до domain mutation, включая no-op reopen уже открытой записи.
Реальный переход дополнительно защищён SQL rowversion при сохранении. Успешный no-op
reopen может вернуть прежний ETag без записи/audit/outbox; это проверка версии на момент
чтения, а не обещание SQL UPDATE или новой версии при любой команде. Настоящие изменения
статуса сохраняют исполнителя, точный срок и связь с наблюдением.

## Интерфейс

- «Мои задачи» и timeline отправляют ETag отображённой строки. При 412 остаются прежняя
  строка и открытый редактор с его исходным черновиком. Автоматического повтора команды,
  подстановки новой версии или скрытого перечитывания после отказа нет.
- Сообщение объясняет конфликт. «Обновить активность» и «Обновить мои задачи» позволяют
  явно перечитать сведения; в обычном timeline ссылка «Проверить текущую активность»
  открывает точную запись M19. Явное обновление выбранной активности по прежнему закрывает
  старый редактор; сам отказ его не закрывает.
- Завершённую Task/Call/Meeting можно снова открыть. Для Note/Email/Cancelled эта новая
  команда не предлагается. Прежнее допустимое завершение открытых записей сохраняется.
- Один ID принимает только одну pending status-команду; разные строки не блокируют
  друг друга. Controls строки сохраняют клавиатурный фокус в disabledFocusable состоянии.
  Прежняя версия после 412 не принимает повторную status-команду до проверки новой записи.
- В выбранной записи клавиатурный фокус переходит между заменяющими друг друга командами
  завершения и повторного открытия. Другой ввод, переход к клиенту, смена сотрудника,
  диалог или скрытие страницы отменяют восстановление. Отсутствующая после чтения строка
  и ошибка также освобождают владельца фокуса, без таймера или перехвата чужого фокуса.

Публикации, развёртывания, новых dependencies, схем БД и вызовов рабочих провайдеров нет.

движках, но оба phone/a11y сценария потеряли фокус после Complete. Отдельная диагностическая

находился на нужной кнопке, но raw `[role=dialog]` ещё существовал: форма/заголовок уже
удалены, пустой DialogSurface высотой около 50 px завершал exit motion. Прежняя проверка

кнопка удалялась, оставляя BODY активным; постороннего ввода/focusin не было. Это отдельная
подтверждённая причина, не предположение о таймаутах. Исходный отказ и диагностические
events сохранены, private runtime и контейнеры обоих запусков очищены.

Исправление использует актуальный lifecycle редактора и реальные ownership/hidden/inert
ограничения, позволяя завершиться пустой анимационной оболочке. Итоговые проверки этой
правки дали 484/484 unit, static/SPA; семь helper-тестов моделируют retained DOM и lifecycle,
новый UI-тест повторяет editor-close → Refresh → Complete/Reopen. Они не моделируют native
анимацию; её проверяют прежние реальные phone assertions. Итоговый новый full-build
composition прошёл 8/8, полный browser-повтор — 55/55, с очисткой owned ресурсов.
Browser assertions, timeout и отсутствие исключений сохранены.
