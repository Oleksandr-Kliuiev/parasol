# M37: импортированные финансы в карточке клиента

Локальный срез поверх истории счетов, клиентского реестра и неизменяемых PDF.
Рабочие аккаунты не подключаются. Azure, новые production dependencies,
публикация и развёртывание отсутствуют; прежние возможности сохраняются.

## Путь сотрудника

Карточка клиента → существующая вкладка счетов → **Счета и кредит-ноты** либо
**Платежи и операции**. Для BillingRead без FinanceRead сохранён прежний обзор
счётов без сумм. Новый раздел монтируется только при наличии обоих разрешений.

Прежние сводные остатки и просрочка сохранены с подписью валюты учёта.
Список счетов показывает вид документа, номер, дату, статус, итого и остаток
в валюте учёта, загружает страницы существующего API. «Просмотр» открывает детали
внутри карточки: суммы в исходной валюте, срок, строки и их покрытие, ссылку
источника/основание при наличии, сохранённые PDF и связанные операции.
Отрицательные суммы кредит-нот сохраняются. Сторнированный документ обозначен
отдельно; ссылка на номер исходного счёта не считается доказательством зачёта.
Старые копии без History остаются доступны вместе с наблюдениями остатка.

Реестр по умолчанию показывает только проведённые платежи; переключатель открывает
все виды операций, включая списания, сторно и прочие записи. Фильтр применяется
на сервере **до пагинации**, а не к уже загруженным строкам. Доступны следующие
страницы, время самого старого сохранённого клиентского снимка и явное отличие
отсутствующего импорта от пустой выборки. Исчезнувшие из последнего снимка строки
остаются в истории с заметным предупреждением; неподтверждённые связи не создаются.

Связь через voucher/match group позволяет открыть точный CRM invoice, в том числе
кредит-ноту. Группа может покрывать несколько счетов: UI не вычисляет сумму оплаты
отдельного счёта. Положительные/отрицательные проводки не переименовываются по знаку.
Подтверждение платежа означает запись в PowerOffice, не независимую банковскую проверку.

Суммы учёта не маркируются выдуманным NOK/EUR. Валюта документа и CurrencyAmount
показываются отдельно, неизвестная исходная валюта обозначается как неизвестная.
UI — просмотр, а не бухгалтерский расчёт: отформатированные числа JS не заменяют
сохранённые в backend десятичные значения и не используются для новых проводок.

## PDF и отказоустойчивость чтения

Каждая захваченная версия доступна для отдельного скачивания, в том числе когда
источник позднее сообщил об отсутствии PDF. Различаются: ещё не проверено,
источник недоступен, явно нет PDF и локально ещё нет сохранённого файла.
Показываются время сохранения, размер и время проверки источника. Сервер повторно
проверяет SHA-256/длину при каждом скачивании; повреждение даёт понятную ошибку,
а прежние исправные версии остаются доступны. Провайдер при просмотре не вызывается.

History, PDF list и download принимают дополнительный `organizationId`.
Несовпадение с текущей привязкой invoice возвращает 404, включая старую ссылку после
перепривязки. Прежние вызовы без этого параметра сохраняют поведение и права.
`customer-ledger` дополнен необязательным `kind`, `sourceCustomers` и
`oldestSnapshotAt`. Новых таблиц и миграций нет.
Постраничный просмотр не является зафиксированным бухгалтерским отчётом: если
локальный импорт обновился во время просмотра, нужно обновить выборку.

Ключи запросов включают клиента и документ, выбранный документ сбрасывается при
переходе к другому клиенту. Параметры клиента передаются и при скачивании.
Несовпадающие идентичности ответов не отображаются. Повторное чтение/ошибка скрывают
предыдущие данные; ошибка не выглядит пустой историей. Детали возвращают клавиатурный
фокус к выбранному счёту. Строки и реестр ограничены по высоте, доступна прокрутка
с клавиатуры; источник JSON, UUID, секреты и внутренние ключи не выводятся в экран.

## Локальная проверка

Предварительно нужны обычные зависимости проекта, восстановленные .NET assets,
Chromium Playwright и закешированный SQL image из `apps/crm/tools/testing/harness/plan.mjs`
(до M38 — `tools/composition/plan.mjs`).
Из `apps/crm/web`:

```sh
npm run e2e:finance -- /absolute/path/to/a/new/private/run-directory
```

Launcher собирает текущую SPA, web и worker, поднимает новый SQL-контейнер только
на loopback, применяет миграции и запускает приложения с ограниченными SQL-ролями.
Все провайдеры выключены, адреса ограничены неиспользуемым loopback. Новые клиенты
создаются настоящим API; test-only CLI заполняет синтетические финансовые снимки
в своей базе и файлы в своём томе. CLI проверяет приватный state, checkout, тестовое
имя БД и принадлежность/loopback контейнера перед каждым SQL-запросом. В приложении
нет fixture endpoint. После прогона удаляются только принадлежащие ему процессы,
контейнер и приватные credentials. Отчёт, снимки экрана и редактированные логи сохраняются.

Пять browser-сценариев работают с настоящим BFF/API и файловым store: пагинация,
счёт → строки → PDF → кредит-нота → платежи; порча файла; права/другой клиент;
четыре ширины в двух темах; русский/норвежский на 320 px. Контрольная сумма реально
скачанного PDF сравнивается с сохранённым SHA-256.
`UI_LAYOUT_AUDIT_MODULE=/absolute/path/to/audit.mjs` дополнительно включает
измеримый layout audit установленного skill; Axe, отсутствие горизонтального
переполнения и скриншоты выполняются всегда.
