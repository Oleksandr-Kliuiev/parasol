# M01–M03: фундамент Parasol

## Реализовано

- M01: отдельный приватный Parasol, полные оригинальные истории, архивные ветки, машинно
  проверяемый manifest импорта. Исходные репозитории и локальные каталоги сохранены.
- M02: `apps/atlas` и `apps/crm`, единые команды bootstrap/build/check из корня, Node 24,
  существующий .NET 10 SDK и собственные lockfiles приложений. Продуктовые границы пока прежние.
- M03: корневой CI для main/PR/manual; проверка истории, build, lint/types, unit/architecture,
  PostgreSQL/SQL integration, coverage CRM и браузерные тесты обоих приложений.
  Общий `Required checks` завершится ошибкой при failed/cancelled/skipped обязательном job.

## Статус приёмки

M01 и M02 проверены локально. Конфигурация M03 создана и проверена actionlint, однако
полная приёмка CI не завершена: GitHub блокирует запуск из-за billing/spending limit,
локальные строгие проверки Atlas выполняются отдельно и не заменяют GitHub CI.
Результаты и ограничения перечислены в `VERIFICATION.md`.

## Необходимые изменения после импорта

В CRM закреплены исправления **уже используемых транзитивных** `System.Security.Cryptography.Pkcs`
и `System.Security.Cryptography.Xml` на 10.0.13. Без этого NuGet Audit останавливал restore
из-за известных уязвимостей. Аудит не подавлен. В web lockfile обновлён существующий
`source-map-js` до исправленной совместимой версии; новые библиотеки не добавлены.
Количество параллельных frontend-тестов ограничено двумя через общий runner/CI:
исходное автоматическое число workers давало таймауты при совместной сборке на рабочем Mac.

После импорта в Parasol исправлены тестовые привязки Atlas к архивным артефактам,
контракт отказа авторизации PowerOffice и тесты команды onboard/бинарных ресурсов.
Механизм [baseline](BASELINE.md) удалён; полные проверки описаны в [ATLAS.md](../testing/ATLAS.md).

## Hostinger

Ни один этап не разворачивает приложение. Активного Azure CI/IaC в корне нет. Исторические
Azure-файлы CRM и ссылки на Azure SDK пока сохранены вместе с исходным приложением.
Перед Hostinger-релизом необходимо отдельно заменить deployment/storage/key persistence,
проверить аутентификацию, резервное копирование и восстановление, подготовить контейнеры,
reverse proxy/TLS и рабочую конфигурацию. SQL Server остаётся временной зависимостью CRM;
его ресурсы и условия эксплуатации либо перенос данных в PostgreSQL нужно решить отдельно.
