# M19 — точное открытие задачи клиента

Локальное продолжение ежедневного сценария Parasol для трёх сотрудников. Несколько задач
одного клиента могут иметь одинаковую тему; прежняя ссылка открывала весь timeline, а
нужная запись могла находиться за первой страницей из 50 элементов. Новая ссылка выбирает
конкретную активность без просмотра промежуточных страниц и копирования текста Atlas.
Публикация, VPS, рабочие credentials и исходные репозитории не затрагиваются.

## Поведение

- Тема в «Моих задачах» и `Open task` в диалоге наблюдения ведут на
  `/organizations/{organizationId}?tab=activities&activityId={activityId}`. В доступном
  имени личной ссылки указан клиент; рядом остаются срок и дата регистрации задачи.
- В карточке виден заголовок «Выбранная активность» и ровно одна запись. Клавиатурный
  переход фокусирует этот заголовок. «Все активности клиента» убирает только выбранный
  ID и возвращает обычный timeline с его прежней пагинацией.
- «Обновить активность» закрывает прежний редактор и перечитывает тот же ID. Во время
  чтения скрыты предыдущие сведения; кнопка сохраняет фокус и не принимает повторное
  нажатие. Это также позволяет после отказа конкурентной правки открыть текущую версию
  без перезагрузки всего браузера.
- На узком экране заголовок панели сохраняет ширину слова, а группа действий переходит
  на следующую строку и переносит кнопки. Длинное тело задачи не растягивает страницу.
- Неверный, пустой, повторный или нулевой ID в URL показывает ошибку ссылки без чтения
  общего списка. Отсутствующая, удалённая или перенесённая запись показывает отсутствие
  выбранной активности у этого клиента; другой объект не открывается автоматически.
- Смена URL, клиента, сотрудника или permissions закрывает прежний редактор и отменяет
  чтение. Поздний ответ или завершение команды не публикует сведения и уведомления
  прежнего scope. Подтверждённый пустой ответ также закрывает старый редактор и не
  восстанавливает его при последующем возвращении записи с тем же ID.
- Редактор сохраняет исходный ETag открытого черновика. Обновление той же записи в фоне
  не повышает эту версию автоматически. `412` сохраняет черновик и сообщает о необходимости
  проверить текущую запись. Остальные правила редактирования M16 остаются в силе.

## Серверный контракт и права

Существующий `GET /api/v1/activities/` принимает необязательный `activityId`. При его
наличии нужен непустой `organizationId`; cursor запрещён. Пустое значение и повторение
query-параметра отвергаются до возможного nullable binding в обычный список. Сервис
также проверяет scope/нулевые ID/cursor для прямых внутренних вызовов.

Точная ветка применяет `organizationId AND activityId` и все остальные переданные фильтры
до выборки одного объекта. Она возвращает прежний `PagedResult<ActivityDto>` с 0/1 строкой,
точным ETag, total 0/1 и `nextCursor: null`. Обычные count/order/cursor/limit не меняются
при отсутствии selector. До и после проекции проверяется пригодность организации;
это ограниченные проверки текущего состояния, а не транзакционный снимок двух модулей.

Сохраняются `ActivitiesRead` для чтения и `ActivitiesWrite` для редактирования. CRM-задача
доступна сотруднику по этим правам без Atlas credentials. `hasTechnicalSource` остаётся
только признаком наличия связи; чтение её деталей по-прежнему отдельно требует AtlasRead
и личного доступа Atlas. Новых provider calls, production dependencies, таблиц или
миграций нет.

## Диагностика unit-окружения

Первый полный frontend получил 450/452: два отсутствующих accessible Dialog при первом
открытии. Исходные DOM-логи обрезаны и не позволяют ретроспективно доказать причину каждого
отказа. Отдельный диагностический повтор двух файлов воспроизвёл 20/21 с точной трассой:
открытый подключённый диалог получает `aria-hidden=true` и остаётся скрытым до timeout;
его закрытие, смена scope или исчезновение portal не происходят.

Локальные исходники jsdom и Tabster объясняют эту трассу: jsdom не моделирует layout и
возвращает нулевой body rectangle и null offsetParent для всех controls. Tabster считает
поля невидимыми, Fluent фокусирует корневой DIV вместо поля, а inactive modalizer скрывает
диалог. Контрольный private A/B, меняющий только эти layout API, прошёл те же 21/21;
трасса показывает фокус INPUT/combobox и отсутствие self-hidden события.

Итоговая test-only модель layout проверяется отдельно на настоящем Fluent Dialog и
отрицательных hidden/detached состояниях. Она не меняет aria-hidden, запросы ролей,
не увеличивает таймауты, не добавляет retries и не меняет production code или packages.
Прежние глобальные `defaultHidden` обходы удалены в шести тестовых файлах; четыре старых
5s/text.closest dialog helper заменены обычным `findByRole` с default timeout. Стандартные
accessible-role assertions усилены. Итоговый полный default-набор прошёл 456/456 без
пропусков, ошибок или предупреждений. Настоящие браузеры остаются отдельными воротами.

Отдельно исправлена обнаруженная ошибка React key в существующем BillingBasisPage:
ключ группы перенесён с дочерней строки на возвращаемый Fragment. Его прежние 6/6
unit прошли, предупреждение missing key исчезло; бизнес-логика биллинга не меняется.

Первый повтор unit после правки мобильной панели дал 454/456. Два теста mapping сразу
после закрытия picker искали кнопку фона синхронно, пока Tabster ещё восстанавливал
доступность фона. Их исправление ожидает кнопку обычным `findByRole` с прежним default
timeout; бизнес-проверки запросов и подтверждения mappings сохранены. Отдельный быстрый
диагностический повтор 18/18 не воспроизвёл отказ и сам по себе не доказывает его причину.

Первый полный CRM browser-run получил 48/49: WebKit не завершил сценарий Back с удержанным
ответом; точное исходное ожидание не было отмечено в трассе. Вместо зависимости от порядка
сетевых событий тест теперь наблюдает настоящий AbortSignal исходного fetch, не меняя
promise, аргументы или ответ. Он требует отмену до освобождения реального HTTP 200,
единственное чтение и отсутствие прежней карточки/редактора после Back. Отдельная
диагностика прошла 3/3 движка. Во всех трёх сетевое событие тоже пришло до освобождения
ответа, поэтому исходная причина timeout остаётся неподтверждённой. Все четыре этапа
ожидания теперь отмечены явно; retries, исключения и увеличенные таймауты не добавлены.

Итоговый повтор всех 49 browser-сценариев прошёл без исключений. Мобильные снимки
390 px в светлой и тёмной теме просмотрены: заголовок целый, действия перенесены,
тело и фокус видны, горизонтального растягивания страницы нет. Проверки клавиатуры,
focus restoration и Axe serious/critical также проходят.
