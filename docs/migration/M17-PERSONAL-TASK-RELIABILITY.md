# M17 — достоверное состояние «Моих задач»

Локальная доработка существующего ежедневного сценария. После M16 read-only аудит выявил,
что ошибка чтения могла выглядеть как «нет задач», а получатель с уже открытым «Моим днём»
не имел явного способа перечитать назначение из другого браузерного контекста. Динамический
Badge завершённых/отменённых активностей также сохранял `subtle + outline` с нечитаемым
текстом в светлой теме. Backend, provider adapters и production dependencies не меняются.

## Требуемое поведение

- Ошибка чтения отличается от подтверждённого пустого списка; прежние строки и source
  controls не остаются под видом нового результата.
- `Refresh my tasks` перечитывает первую страницу, очищает прежние продолжения и закрывает
  source controls предыдущей ревизии. Получатель может явно получить новое назначение,
  оставаясь на уже открытой странице. Автоматический polling не вводится.
- Личная выборка привязана к сотруднику и его permissions. Смена scope убирает прежние
  строки, страницы, ошибки и открытые источники; поздний ответ их не возвращает.
- Следующая страница запрашивается только явным действием. Счётчик отражает загруженные
  строки и последний полученный total, а не неизменяемый снимок всей очереди.
  Повторный ID после изменения срока/статуса не дублирует строку; последняя полученная
  версия Activity используется для отображения, shown считает разные ID.
- Completion controls доступны при ActivitiesWrite; Atlas source сохраняет свою отдельную
  проверку AtlasRead. Серверные права и complete/reopen контракт M16 не расширяются.
- Поздний ответ completion после смены сотрудника/permissions не публикует тему прежней
  задачи или ошибку в новой сессии. Уже отправленная серверная операция не отменяется
  и не повторяется; подавляются только UI effects завершившегося личного scope.
- Нейтральные Badge Done/Cancelled используют читаемый `informative + outline`.

## Проверка

Нужны осмысленные frontend-регрессии ошибки/восстановления, refresh с очисткой продолжения,
смены сотрудника/permissions и позднего ответа, paging и read-only completion controls.
Браузерная проверка должна измерить вычисленный контраст завершённых/отменённых Badge
в обеих темах. Полный frontend, TypeScript, ESLint и бюджет SPA остаются обязательными.

Существующий настоящий composition handoff усиливается без изменения числа сценариев:
получатель открывает «Мой день» до создания Task другим сотрудником, затем ручным refresh
получает назначение и завершает его. Точные одна Task/receipt/create-audit, два ActivityLogged,
privacy и cleanup сохраняются. Итоговый текущий браузерный набор прошёл 38/38; полный
[composition](../testing/evidence/composition-current-2026-10-16.json) со сборкой обоих
приложений прошёл 8/8, включая этот усиленный сценарий. Пропусков/retries нет, ресурсы очищены.

## Последующее точное открытие задачи

Несколько технических задач одного клиента имеют намеренно одинаковую generic subject.
На момент M17 ссылка открывала весь timeline. Следующий [M19](M19-EXACT-ACTIVITY-NAVIGATION.md)
добавляет organization-scoped activityId-фильтр существующего списка и фокус выбранной
записи, без page walking и копирования Atlas text. Его read-контракт и проверки описаны
отдельно; приведённые ниже результаты остаются историческими результатами M17.

Frontend реализован: полный набор 415/415 в 50 файлах, без skipped/errors/warnings;
адресный набор 17/17, TypeScript, E2E/composition TypeScript и полный ESLint проходят.
Независимая проверка финальных scope, paging, permission и notification fences завершена
без оставшихся замечаний в этом объёме. SPA проходит бюджет 290,5/300 KB. После последней
правки фокуса M10/M11 отдельно пройден адресный frontend-набор 56/56; он не выдаётся за
повтор полного 415. Текущее совместное свидетельство относится к исходникам после M17/M18.
