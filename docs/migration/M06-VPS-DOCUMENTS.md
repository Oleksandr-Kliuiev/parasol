# M06 — хранилище документов VPS

PR #3 (M05) слит merge-коммитом `d17ca6d`, история исходных проектов сохранена.
Эта часть M06 заменяет Azure Blob файловым хранилищем для постоянного тома Hostinger.

## Реализовано

- Единый `IDocumentStore` для web/worker: атомарная публикация без перезаписи между
  процессами, синхронизация файлов/каталогов, хеш и длина фактически сохранённых байтов.
- Production требует абсолютную существующую папку и совпадающий UUID тома; ошибки
  mount, доступа и синхронизации не скрываются. Запуск проверяет возможности хранилища.
- Канонические ключи, запрет symlink, скрытые staging-файлы и уборка старых staging.
- Публичных URL нет. SQL-защита Ready-документов, проверка хешей, privacy/maintenance,
  восстановление и очистка ссылочных документов сохраняются.
- Azure Blob SDK, Azurite и неиспользуемые Azure DataProtection packages удалены.
  Новых production-зависимостей нет. Импортированные Bicep и тесты исторической
  инфраструктуры сохранены как архив; они не запускают развёртывание.
- Проверки независимых процессов, остановки автора на границах записи и восстановления
  файлов в новую папку добавлены к существующим unit/SQL integration проверкам.

Дизайн: [ADR-026](../../apps/crm/docs/adr/ADR-026-vps-document-store.md).
Настройка, перенос и восстановление: [runbook 16](../../apps/crm/docs/runbooks/16-vps-document-storage.md).

## Граница этапа

Код готовится к Hostinger; рабочий VPS и реальные данные не менялись. Следующий шаг —
пакет развёртывания, постоянные тома и секреты, TLS/reverse proxy, backup и учение restore.
Azure Blob больше не является production-зависимостью документов. Остальные исторические
Azure-настройки приложения не превращают этот PR в готовое развёртывание всего продукта.
Исходные репозитории Atlas/CRM и их локальные изменения не изменяются.
