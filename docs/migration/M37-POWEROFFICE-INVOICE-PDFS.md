# M37: оригинальные PDF счетов и кредит-нот PowerOffice

Локальная разработка на синтетических данных. Рабочий PowerOffice не подключался,
публикация и развёртывание не выполнялись. История счетов, клиентских операций,
исходящий обмен и остальные возможности сохраняются.

## Контракт источника

Публичная [OpenAPI Voucher Documentation](https://swagger.poweroffice.net/openapispecs/voucherdocumentation.json)
проверена 2026-10-18. `GET VoucherDocumentation?id=<voucher UUID>` возвращает
`VoucherId`, `VoucherType`, `HasPdf`. `GET VoucherDocumentation/Download?id=<UUID>&documentationType=Pdf`
возвращает **ZIP**, содержащий PDF, а не один PDF. Оба метода требуют роли источника
`VoucherDocumentation` или `VoucherDocumentation_Full`. Приложение использует только GET;
права записи в PowerOffice для этого импорта не нужны. Существующий OAuth token POST сохраняется.
UUID исторического `OutgoingInvoices.Id` является UUID проведённого voucher;
номер счёта может повторяться и никогда не служит ключом PDF.

## Поведение

- Отдельный `poweroffice-invoice-pdfs` включается только через
  `Integrations:PowerOffice:InvoicePdfSyncEnabled=true` (по умолчанию false).
  `InvoicePdfSyncCron` по умолчанию `45 2 * * *`, Europe/Oslo.
- Job получает сохранённые исторические счета и кредит-ноты страницами по 200,
  под общим эксклюзивным lease PowerOffice. Все UUID проверяются заново при каждом
  запуске: PDF может появиться позже или измениться без изменения баланса счёта.
  Неизвестные/старые счета без доказанного source UUID не сопоставляются по номеру.
- Проверяется точное совпадение UUID и типа invoice/credit note, наличие `HasPdf`,
  отсутствие дубликатов metadata. Пустая metadata-выдача означает недоступную документацию
  (`sourceHasPdf=null`); явное `HasPdf=false` сохраняется отдельно. Неудачный запрос
  не объявляется успешной проверкой и не меняет предыдущую запись проверки.
- `HasPdf=true` требует полного ZIP и хотя бы одного PDF. HTTP 204/403, HTML,
  неверный media type, повреждённый/обрезанный архив или ошибочный элемент прерывают
  этот счёт. Уже завершённые счета остаются сохранёнными; следующий запуск безопасно
  повторяет обход. Job сообщает ошибку через обычные SyncRuns, без тела ответа в сообщении.
- Лимиты: ZIP 60 MiB, максимум 20 файлов, PDF 30 MiB, сумма распакованных данных
  100 MiB. Чтение ограничено фактическим числом байтов, не только Content-Length.
  Имена проверяются; файлы не распаковываются на диск по именам архива. Архив с
  не-PDF элементами/папками, повторными именами или шифрованием отклоняется целиком.
- ZIP CRC32 и длина проверяются для каждого элемента. PDF проходит ограниченную
  проверку оболочки `%PDF-...` / `%%EOF`; это не полный PDF-парсер и не антивирус.
  PDF не перерисовывается: сохраняются оригинальные байты.

## Хранение, неизменность и повтор

`billing.InvoiceDocuments` содержит ссылку на CRM invoice, исходное имя, SHA-256,
длину, ключ и время первого импорта. Уникальность `(InvoiceId, SourceName, ContentSha256)`
защищена SQL; исходное имя сравнивается бинарно. Все документы одного счёта и результат
проверки `billing.InvoiceDocumentChecks` публикуются одной SQL-транзакцией под общим
invoice lock. Импорт повторно проверяет source UUID, систему и тип уже внутри транзакции.

Используется существующий VPS `IDocumentStore`, ключ
`billing/invoice-pdfs/<CRM invoice UUID>/<content SHA-256>.pdf`. Запись create-only;
перед записью SQL сверяются возвращённые metadata **и повторно прочитанные байты**.
Чужой/повреждённый существующий объект не подхватывается. После обрыва записи или
SQL rollback файл может остаться без строки БД; повтор использует тот же ключ,
проверяет байты и добавляет единственную строку. Автоочистки этого namespace нет;
такие файлы сохраняются для восстановления, требуется контроль свободного места.

Изменённый файл источника добавляется как ещё одна неизменяемая версия; старые PDF
остаются доступны. Список показывает все захваченные версии, а не утверждает,
что каждая из них всё ещё является текущим документом PowerOffice. `NoPdf` и исчезновение
документации у источника не удаляют ранее сохранённые версии. Изменение ZIP-паковки
без изменения имени и PDF-байтов не создаёт дубли. Несколько имён одинакового PDF
дают разные metadata-ссылки на один объект.

Runtime SQL-роли запрещены UPDATE/DELETE InvoiceDocuments и DELETE InvoiceDocumentChecks.
Миграция только добавляет таблицы; downgrade при наличии любого нового состояния
запрещён, прежние счета/строки/платежи не изменяются. Владелец SQL/диска остаётся
доверенным оператором, аппаратный WORM не заявляется.

## Чтение и восстановление

- `GET /api/v1/billing/invoices/{id}/documents`: все захваченные PDF + последняя
  доступность и время успешной проверки. До первого обхода `checkedAt=null`.
- `GET /api/v1/billing/invoices/{id}/documents/{documentId}/download`: только документ
  этого invoice, только после повторного SHA-256/length check. При повреждении или
  отсутствии файла возвращается ошибка без байтов. Скачивание attachment, no-store,
  nosniff; имена для скачивания формируются из внутреннего UUID.
- Оба метода требуют **BillingRead и FinanceRead**. Привязка к клиенту следует
  сохранённому invoice: его безопасное переподключение не копирует и не переносит PDF.
- `IRestoreParticipant`, область `billing-documents`, проверяет SHA-256 и размеры
  всех ссылочных PDF и требует вмешательства при отсутствии/порче. Существующий
  backup всего тома документов включает новый namespace. Учение на Hostinger не запускалось.
  Отсутствующий файл можно восстановить из резервной копии либо повторно получить
  идентичные байты источника; повреждённый существующий ключ не перезаписывается.

SHA-256 доказывает соответствие захваченным байтам, а не юридическую подлинность PDF:
PowerOffice API не предоставляет независимую цифровую подпись/контрольную сумму в этом
контракте. Семантическая сверка итогов PDF со строками, malware scanning, EHF, изображения,
вложения SalesOrders, UI, рабочая миграция и выбор правового срока хранения — отдельные этапы.
Как и предыдущие части M37, импорт использует один namespace `poweroffice`: переключение
рабочей компании/аккаунта без отдельной миграции namespace не поддерживается.
Опциональный PDF stream пока не включён в агрегат готовности M15; ошибки видны в SyncRuns.
