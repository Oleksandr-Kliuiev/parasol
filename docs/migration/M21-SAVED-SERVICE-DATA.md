# M21 — достоверные сохранённые данные Service

Локальный шаг для ежедневной работы: сотрудник должен отличать отсутствие сохранённых
заявок/устройств от ошибки чтения и понимать, что данные CRM не являются live-проверкой Atera.
Новых провайдеров, production dependencies, схем БД, публикации или развёртывания нет.

## Поведение

1. Summary, Tickets, Devices, Open alerts и Ticket requests показывают loading/error/empty
   независимо. Пока summary неизвестен, числовые tiles и device totals не рисуют нули.
   Ошибка summary не скрывает успешно прочитанные остальные разделы.
2. «Обновить сохранённые данные» перечитывает пять локальных GET с первой страницы.
   Это не sync Atera, не provider call и не POST. Повторная активация не дублирует refresh;
   кнопка сохраняет фокус. Продолжение страницы можно отменить этим обновлением.
3. Каждый список может повторить своё чтение отдельно. Ошибка страницы или poll не
   показывает старые rows/totals как актуальные. Retry начинает первую страницу с теми
   же фильтрами, а прежние cursor/late replies не возвращаются.
4. Query lifetime включает сотрудника, permissions, клиента и read revision. Старые
   запросы отменяются; gcTime 0, без автоматических retry/focus/reconnect refresh.
   Существующий пятисекундный опрос Pending requests сохранён. Ошибка опроса останавливает
   его до явного Retry/Refresh; успешный Pending снова включает опрос, Failed/empty — нет.
5. Прежняя форма заявки выделена в отдельный компонент. Поля, payload, contact400,
   ServiceWrite и сохранённые defaults остаются прежними. Поздний ответ старой формы не
   закрывает новую форму, не показывает старое уведомление и не перечитывает нового owner.
6. `lastSyncedAt` остаётся прежним серверным полем MAX(Ticket.SyncedAt). Его честная
   подпись — последнее изменение сохранённой заявки; null означает неизвестное время.
   Это не время последнего успешного sync, не свежесть устройства и не текущая доступность Atera.
7. Вкладка клиента, выбранная URL, видна на телефоне. Reveal двигает только горизонтальную
   прокрутку TabList, сохраняя фокус и вертикальную позицию страницы; resize и смена языка/
   доступных вкладок также учитываются.

## Проверки

Текущие исходники проверяются локально на синтетических данных:

- Новый адресный Service-набор — 30/30 в четырёх файлах, включая прежнюю пагинацию
  1100 устройств. Полный default-набор — 513/513 в 59 файлах, без skipped/errors/warnings.
- Полный ESLint, app/E2E/composition TypeScript и SPA 290,5/300 KB проходят. Все 371
  source/build/test web inputs совпадают по SHA256 до и после итоговых проверок.
- Первый полный unit получил 512/513: тест после смены клиента синхронно искал кнопку;
  DOM-лог в этот момент показывает фон с aria-hidden=true после закрытия старой формы.
  Использовано обычное findByRole с прежним default
  timeout; проверки позднего POST, отсутствия GET/toast и сохранности новой формы прежние.
- Полный composition (свидетельство удалено в M38:
  `git show 73c0158:docs/testing/evidence/composition-M21-2026-10-17.json`) с новой
  сборкой CRM и прежнего сервиса интеграций (удалён в [M38](M38-OPERATIONS-IN-CRM.md)) — 8/8,
  0 skipped/unexpected/flaky; одна Task/receipt/create audit, два ActivityLogged, privacy
  evidence, restricted roles и cleanup проходят. Recorder переслал 564 запроса к прежнему
  сервису, mutating requests — 0. CRM browser — 67/67,
  без skipped/unexpected/flaky/retries; owned runtime очищен. Предыдущий M20 сохранён отдельно.

Итоговое свидетельство M21 (удалено в M38:
`git show 73c0158:docs/testing/evidence/saved-service-M21-2026-10-17.json`)
содержит текущие результаты. Первый browser-прогон 63/67 сохранён: Axe выявил
нефокусируемую горизонтальную таблицу Tickets; оба сбоя входа WebKit показывали
в AuthGate «Too many requests». Таблица получила именованную область с видимым фокусом;
реальная прокрутка ArrowRight и Axe проходят в обеих темах. Только isolated browser-fixture
использует тот же API budget, что существующий E2E config; production/composition defaults
не менялись. Сырые HTTP-трассы первоначального 429 не сохранялись.

Backend SQL 38/38 и architecture 94/94 повторно не запускались: все 775 исходных входов
совпадают по SHA256. Код прежнего сервиса также не изменён: 1421 вход совпадает со строгими
711 unit / 789 PostgreSQL / 90 browser. Сохранность исходных Git HEAD/status/refs,
import history, diff-check и secret scan проверяются перед локальным checkpoint.

Новые unit проверяют все пять held/error/retry состояний, continuation failure и reset,
AbortSignal при scope change, старые ответы, gcTime 0, Pending poll/ошибку/ручное
возобновление, contact400 и форму. Браузеры используют настоящий локальный API/SQL:
одна 503-инъекция и удержанные настоящие ответы проверяют состояния и отмену; отдельные
сценарии проверяют keyboard/Axe и существующие часы/согласование/отключённую Atera.
