# M16 — срок, исполнитель и конфликт правок задачи

Локальная доработка существующего CRM-редактора Activities. Задача, созданная из наблюдения
Atlas, редактируется в том же интерфейсе; отдельный редактор или новый API не добавляются.
Публикация, развёртывание и подключение рабочих аккаунтов в этот этап не входят.

## Сохранение срока

API хранит момент времени, а `datetime-local` показывает местное время браузера. Прежний
редактор обрезал UTC-строку и затем повторно интерпретировал её как местное время: правка
исполнителя или текста могла сдвинуть срок на один или два часа в Europe/Oslo и удалить
секунды/миллисекунды.

Новый draft преобразует исходный момент в местное значение при открытии. Пока пользователь
не меняет это значение, отправляется точная исходная строка, включая секунды, миллисекунды
и смещение. Это также сохраняет выбранное в исходных данных вхождение повторяющегося часа
при переходе с летнего времени. Очистка отправляет `null`; явно изменённый местный срок
преобразуется в UTC. Невалидное значение блокирует отправку и показывает ошибку поля.
Преобразование также проверяет обратное местное значение: несуществующий час весеннего
перехода и автоматически нормализованная дата не превращаются молча в другой срок.

## Сохранение черновика

Форма удерживает ETag версии, на которой был начат draft. Обновлённые props той же записи
не дают старому черновику ETag чужой новой версии. Открытие другой записи создаёт новую форму.
Серверный конфликт не вызывает автоматического повтора или перезаписи; введённые данные
остаются для разбора пользователем.

Поздний ответ закрытой или заменённой формы не закрывает новый редактор и не меняет его
ошибки/уведомления. Временная блокировка редактируемых полей при сохранении предотвращает
потерю более новых, ещё не отправленных правок. Cancel остаётся доступен; уже отправленная
серверная операция при закрытии формы не отменяется и автоматически не повторяется.

Отказ назначения `ACT_SOURCE_TASK_ASSIGNEE_INVALID` без field errors теперь получает
понятное сообщение формы. Для HTTP 409/412 показывается пояснение о конфликте с сохранением
черновика. Общий текст для этих статусов существовал и прежде; он не описывается как
полностью отсутствовавший. Обычные ошибки полей сохраняются, исходный текст сервера не
подставляется в специализированные сообщения. Явная правка или новая отправка убирает
прежнее сообщение формы.

## Существующая серверная граница

`PUT /api/v1/activities/{id}` требует ActivitiesWrite и If-Match. Для source Task тип и
клиент неизменны; смена исполнителя проверяет его активность и ActivitiesWrite + AtlasRead.
Неизменённый неактивный исполнитель не мешает редактировать или завершать прежнюю задачу.
Source receipt сохраняется, технический payload не копируется в обычную Activity или audit.

Конкурентная правка PUT получает 412, отсутствие If-Match — 428. Существующие complete/reopen
используют tracked SQL rowversion, но не имеют клиентского If-Match-контракта. Этот этап
не меняет их API и не заявляет для них сравнение версии открытого пользователем draft.
Task-операции не вызывают Atlas или внешнего провайдера.

## Проверка

Frontend-регрессии охватывают зимнее/летнее время, оба вхождения повторяющегося часа,
сохранение точного срока при правке другого поля, изменение/очистку срока, сообщения
отказа, сохранение draft и исходного ETag, поздние ответы прежней формы и блокировку полей
во время сохранения. Проверка Europe/Oslo выполняется в отдельном процессе, без изменения
timezone общего Vitest runtime.

SQL-регрессия использует двух заранее аутентифицированных сотрудников: оба читают E0,
первый назначает второго и меняет срок, получает E1; PUT второго с E0 и PUT без заголовка
не меняют Task, её audit/outbox или receipt. Complete/reopen сохраняют новый срок,
исполнителя и source identity. Производственный серверный код не изменяется.

SQL-проверка прошла 14/14 без пропусков: новая регрессия и 13 прежних SourceTaskApi tests.
Web/Integration Release-сборка получила 0 warnings/errors. Использована точная копия
761 source/test файла; только scratch factory получила закреплённый cached SQL Server
image, новый loopback port и метку владения. Fixture удалён, private credentials очищены.
Серверный код и общая factory не менялись. Итоговый полный frontend прошёл 399/399 в 49
файлах, без пропусков/errors/warnings; адресный набор — 19/19. TypeScript и полный ESLint
проходят, независимая проверка финальной границы draft/ETag/lifetime/pending controls не
выявила оставшихся замечаний в этом объёме. SPA проходит бюджет 290,5/300 KB.

Текущий браузерный повтор карточки, очереди, source handoff, внимания, readiness и отзыва
доступа прошёл 38/38 без пропусков/retries, обе темы и три движка; cleanup подтверждён.
[Полный composition](../testing/evidence/composition-current-2026-10-16.json) со сборкой обоих
приложений прошёл 8/8 с точным durable/privacy/role evidence и cleanup. В этом браузерном
сценарии задача создаётся, завершается и повторно читается; PUT-редактирование срока и
исполнителя проверяется отдельно указанным SQL-набором и frontend form-регрессиями.
