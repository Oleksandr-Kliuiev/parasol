# Локальная демонстрация Parasol

Стенд для проверки удобства на одном компьютере: 40 синтетических клиентов,
400 устройств и три роли сотрудников. Работают настоящие CRM Web/Worker и Atlas API
с отдельными SQL Server/PostgreSQL и ограниченными runtime-ролями. Atera, Huntress,
PowerOffice, Graph и отправки наружу не подключаются. Устройства и наблюдения взяты
из локальной синтетической базы; сохранённая заявка также тестовая.

## Запуск и остановка

В корне Parasol, с установленными Node 24, .NET 10, Docker, OpenSSL и зависимостями
проектов ([подготовка совместного стенда](COMPOSITION.md)):

```sh
PARASOL_DEMO_BASE="$(node -p 'require("node:fs").realpathSync(require("node:os").tmpdir())')"
npm run demo:local -- --directory "$PARASOL_DEMO_BASE/parasol-demo-review-01" --minutes 30
```

Каталог должен быть новым. Для повторения используйте другой суффикс, например `-02`.
Команда собирает текущие исходники; затем печатает локальный HTTPS-адрес, три ссылки
входа и время окончания. Таймер начинается после готовности, по умолчанию 30 минут,
допустимо 1–120. Образы БД должны быть уже закешированы: автоматического pull нет.

Оставьте терминал работающим. Откройте напечатанную ссылку `Crm.Admin` в отдельном приватном окне браузера.
Временный сертификат localhost может потребовать подтверждения в браузере; системное
хранилище доверия команда не меняет. Вход Development использует тестовую роль,
пароль Microsoft 365 и рабочие ключи в этом стенде не нужны.

Если панель Codex показывает `ERR_CERT_AUTHORITY_INVALID`, откройте напечатанную командой
ссылку в обычном локальном браузере, например Chrome, в отдельном приватном окне.
Панель может показать только страницу ошибки, без возможности временного перехода.
Подтверждение предупреждения для этого localhost выполняет сам пользователь, если
браузер предлагает такой переход. Это отличается от установки сертификата в системное
хранилище доверия: для демонстрации такая установка не предусмотрена.
Если браузер не предлагает переход, для разбора сохраните точное название ошибки.

**Ctrl+C** в терминале или истечение таймера останавливает собственные приложения,
удаляет только принадлежащие запуску контейнеры и очищает private-файлы. После этого
`demo.json` показывает `status: stopped`, причину остановки и `cleanup: true`.
`report.json` остаётся диагностическим, `accepted: false`: демонстрация не заменяет
автоматическую тестовую приёмку. При ошибке посмотрите ограниченный report; повторный
запуск всегда создаёт новый стенд. Данные предыдущего запуска не восстанавливаются.

Адрес доступен только на этом компьютере. Стенд не развёртывается на VPS. Настройки
системного браузера, существующие репозитории, пользовательские контейнеры и рабочие
подключения не изменяются. Подробные журналы и private-файлы не нужны для обратной связи.

## Проход за одного сотрудника и передача работы

Подписи ниже соответствуют английскому интерфейсу; язык можно сменить в профиле.
Используйте только синтетические записи стенда.

1. Войдите по ссылке **Crm.Admin**. На «Моём дне» найдите **Synthetic Client 01 AS**.
   Откройте карточку клиента и технический блок Atlas. Проверьте устройства, происхождение
   данных и предупреждения об устаревшем/отсутствующем снимке. Одинаковые hostname
   относятся к разным ID устройств.
2. Выберите активное наблюдение, например **Synthetic older critical security incident**.
   Нажмите **Assign work**, выберите сотрудника с ролью Technician, задайте срок и
   подтвердите создание задачи. Исходное наблюдение остаётся отдельной записью Atlas.
3. Откройте напечатанную ссылку **Crm.Technician**. В **My tasks** нажмите
   **Refresh my tasks**. Откройте **View Atlas source** и убедитесь, что понятны клиент,
   источник и причина работы. Закройте окно.
4. В той же строке нажмите **Service ticket** → **Choose saved ticket**. Выберите
   **#910002 · Synthetic saved service ticket**, затем **Link selected ticket**.
   Это связь с сохранённой тестовой заявкой, без обращения к Atera.
5. Нажмите **Register hours**. Часы и описание изначально пустые. Введите, например,
   `0.25` и «Проверил тестовое наблюдение», затем сохраните. Клиента, устройство,
   ticket ID и текст наблюдения переписывать не нужно. Сохранение часов само по себе
   не завершает задачу и не закрывает наблюдение Atlas.
6. Закройте окно заявки. После изменения связи список автоматически перечитает полную
   задачу; фокус вернётся на **Refresh my tasks**. Дождитесь чтения, проверьте текущие
   сведения и завершите задачу. Обновите личный список:
   завершённая задача исчезнет из открытых. В карточке клиента она остаётся в Activities.
   Удалять тестовые данные вручную не требуется — стенд очистится при остановке.

У Admin доступны 40 клиентов Atlas, у Technician — первые 20, у ServiceLead — другие
20. Для проверки границы откройте ссылку **Crm.ServiceLead**: клиент 01 не становится
доступным в Atlas только из-за роли CRM. Если нужны одновременные роли, используйте
разные профили браузера: вкладки одного профиля разделяют сессию. Для последовательного
прохода достаточно открывать ссылки ролей по очереди.

## Устройства, наблюдения и навигация

В карточке клиента выберите **Devices**, **Observations** или полную очередь. Длинные
списки прокручиваются внутри блока; Tab переводит фокус в переполненный список, End
доходит до последних загруженных строк. Поиск относится к загруженной странице;
для остальных записей используйте штатную загрузку/очередь. На широком экране реквизиты
клиента остаются рядом, на узком — ниже. Мягкий край показывает продолжение прокрутки.
Проверьте также названия вкладок браузера и первую ссылку **Skip to content**: Enter
переводит фокус в main и оставляет заголовок ниже закреплённой панели.

## Дополнительная проверка Microsoft 365

В текущем M31-стенде Admin может открыть вкладку **Microsoft 365** клиента 01: одна
сохранённая запись пользователя, одна устаревшая облачная регистрация устройства и
недоступное покрытие входов за 24 полных часа UTC. Раскройте интервал без покрытия
с клавиатуры и нажмите **Refresh Microsoft 365**. Это чтение тестовой БД, не Graph.
Регистрация устройства не увеличивает десять машин клиента и не считается лицензией.

У Technician в фикстуре есть только context:read: вкладка сообщает об отказе M365,
повторно проверяет общий контекст и позволяет вернуться к десяти устройствам Atlas.
Это различие синтетических прав, не проверка рабочих Entra ролей. Совместная M31-приёмка
прошла 10/10 с новой сборкой; описание не заменяет её отчёт или человеческую оценку удобства.

## Что зафиксировать

Для каждого прохода запишите только роль A/B/C, длительность по секундомеру, число
лишних переходов, что пришлось копировать вручную и где результат был непонятен.
Не включайте настоящие имена клиентов, учётные записи, пароли или ключи.

| Проверка | Наблюдение сотрудника |
| --- | --- |
| Понятно, что требует внимания и насколько свежие данные | |
| Легко выбрать устройство и проверить источник | |
| Понятны исполнитель, срок и результат создания задачи | |
| Получатель находит работу и её контекст | |
| Заявка и часы доступны без повторного ввода клиента/ID | |
| Понятно, что произошло после сохранения/завершения | |
| Клавиатура, узкий экран и выбранная тема удобны | |
| Время всего прохода и самая длинная пауза | |

Автоматическая длительность теста не является экономией времени сотрудника. Для
сравнения повторите аналогичную задачу привычным способом и отдельно измерьте её.
Отзывы по этому проходу определяют следующие исправления. Настоящие аккаунты,
финансовая историческая сверка, Entra и Hostinger VPS требуют отдельной приёмки.
