- **Backfill formula matches the pre-reset invariant.** Before any reset, charges since the last publication equal started minus published, because failures and crashes advance only started. Capping at eight yields exhaustion for over-tried chains instead of a fresh budget, as the plan states.
- **Backoff bound.** The existing delay function reaches its cap at the sixth charged attempt from the 30-second base, so eight attempts do reach the cap. The 429 branch returns the exact bounded Retry-After or the 60-second fallback plus jitter, untouched.
- **Atomic first-state admission.** INSERT ... ON CONFLICT DO NOTHING waits on a concurrent uncommitted insert, so the loser's SELECT FOR UPDATE sees the committed row and takes the next sequence. State rows are never deleted by cleanup, so the row cannot vanish between the two statements. The generation trigger reads the state row FOR SHARE in a later statement, which the claim already holds FOR UPDATE.
- **Reset obeys every frozen guard.** Advancing recorded to the new started value satisfies the retryAt trigger's newest-recorded rule, so clearing an elapsed retryAt is admitted. PENDING must leave PENDING once recorded is non-zero, which the ERROR/M365_CLAIM_EXPIRED normalization does. A retained pointer with ERROR passes the pointer check. Published sequence and pointer are untouched, so the publication fence is not exercised.
- **Old-claim fencing after reset.** Page staging, publication and failure recording all compare the generation's attemptSeq with latestStartedSeq, and the publication trigger does the same under the state lock. A delayed claim can only mark its own generation FAILED, never the state row.

Cleanup takes Connection FOR NO KEY UPDATE, so reset and cleanup serialize. A concurrent claim that wins leaves an unexpired STAGING generation, which the reset refuses.
