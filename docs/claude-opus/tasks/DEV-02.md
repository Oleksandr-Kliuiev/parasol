# DEV-02 Согласования конкретной версии расчёта

Приоритет: **P1**. Аудит: **A02**.

Зависимости реализации: DEV-01. Проверки: Q1, Q2, Q3.

Внешняя приёмка: не требуется отдельный внешний gate; нужны фактические локальные доказательства.

## Контекст

Проверка разных согласующих асимметрична. Пересборка не очищает approvals. Порог рассчитывается только при сборе.

## Результат

Утверждение относится к неизменяемой ревизии и текущей сумме; две подписи принадлежат разным людям.

## Объём реализации

1. Ввести ContentRevision или эквивалент и привязать каждое согласование к нему; определить канонический digest состава. Успешная пересборка и изменение финансового содержания аннулируют действующие согласования.
2. В транзакции утверждения проверять текущие суммы, порог и актуальность ревизии. Сохранить правило проекта: порог применяется к основанию клиента, сумма без НДС; исходное сравнение строго больше порога. Смена правила требует решения Finance.
3. Требовать If-Match на пользовательских командах утверждения/изменения; изменения дочерних строк должны конфликтовать с параллельным утверждением родителя.
4. Отклонять null/неактивного пользователя и одинаковых людей при любом порядке действий, включая Admin с обоими правами. Выбрать и документировать порядок согласования; UI не должен разрешать несовместимый переход.
5. Записывать событие постановки на экспорт только при успешной фиксации approved-снимка. Повтор команды не создаёт новый внешний эффект.
6. Показывать в UI, какая версия ожидает согласования, кто согласовал и почему подписи сброшены.

## Критерии приёмки

- **DEV-02-AC01** — Все три регрессии A02 проходят и имеют проверки API, не только домена.
- **DEV-02-AC02** — При настроенном пороге 200000 суммы 199999.99 и 200000 следуют существующему правилу; 200000.01 требует второго человека.
- **DEV-02-AC03** — Ручная строка 300000 после сбора с RequiresSecondApproval=false не может пройти одно согласование.
- **DEV-02-AC04** — Старый ETag даёт 412, отсутствующий на требуемой команде — 428; изменение строки одновременно с approve не проходит незаметно.
- **DEV-02-AC05** — Повторное утверждение, несколько вкладок и worker не размножают BillingRunApproved/BillingBasisApproved экономически.
- **DEV-02-AC06** — Отклонённое утверждение не меняет подписи, статус и outbox частично.

## Данные и обратимость

Существующие утверждённые/выгруженные основания сохранять как legacy sealed revision. Незавершённые согласования мигрировать в состояние повторной проверки с объяснением; журнал прежних решений не удалять. Проверить EF execution strategy и транзакции SQL Server.

## Границы

Не давать Admin исключение из двух согласующих; не превращать сумму всего прогона в порог одного клиента.
