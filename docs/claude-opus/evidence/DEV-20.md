- Задание: `tasks/DEV-20.md`. Рабочую миграцию при разработке не выполняли.

## Найденное и сделанное

Анализ текущего кода подтвердил дефекты; главный — **гарантия «импорт не затирает то, что набрали в CRM» была ложной**: при повторном импорте для найденной организации обнулялись ответственный менеджер, технический ответственный, форма, NACE, счётный e-mail, EHF, адреса, домены, подменялись название и оргномер.

| Было | Стало |
|---|---|
| Update затирал поля CRM | `Organization.FillGaps`/`FindConflicts`, `Contact.FillGaps`…: пустое заполняется, непустое не меняется никогда; отличие в файле — `Conflict` с кодом `FIELD_CONFLICT` и **именами** полей; совпадение по домену/названию при другом оргномере = другая компания; платёжные поля не трогаются, если мастер — PowerOffice |
| Событие `OrganizationUpdated` на каждой совпавшей строке | Только при реальном изменении; Updated/Unchanged считаются по факту |
| Контакты: «—» вместо имени, обнуление телефонов, счётчик «записано» врал, без e-mail создавались повторно | Fill-only, считаются реальные записи, без e-mail сопоставление по (организация, нормализованное имя); один e-mail в строках разных организаций — один человек с несколькими привязками |
| Дубли внутри файла: предпросмотр «создано», реальный прогон падал на индексе | `DUPLICATE_IN_FILE` в обоих режимах |
| Нет манифеста, одна транзакция на 5000 строк, нет возобновления | `ImportRuns`, `ImportRowOutcomes`, `ImportRunEntities` (отпечаток SHA-256, версия отображения, ключ повтора, исходы по строкам, маркёр партии); чанки по 200 строк, `Partial` с диапазоном сбоя, возобновление после последней зафиксированной строки |
| Проверки качества | ~20 кодов отклонения (`INVALID_ORGNR`, `INVALID_EMAIL`, `UNKNOWN_STATUS`, `BROKEN_REFERENCE`, `AMBIGUOUS_DATE`, `INVALID_CURRENCY`, `INVALID_VAT_RATE`, `OWNER_UNKNOWN`…) и предупреждения (`NEAR_DUPLICATE` без слияния и без связывания, `OWNER_EMPTY`, `UNKNOWN_PRODUCT`); колонки владельца, внешних ID, родителя, договорных дат, валюты, НДС, продукта проверяются и показываются как «проверено, не импортировано» |
| `CsvTable` | RFC 4180 (многострочные значения), физические номера строк, ragged rows, BOM, неоднозначные даты `03/04/2026` не угадываются |
| Предпросмотр внешних записей (`ExternalImportService`) не совпадал с реальным | Одни и те же решения, счётчик ошибок автосвязывания, ошибки без имён |
| Сверка с кассой старой системы отсутствовала | `POST …/import/reconcile`: файл `оргномер;период;валюта;сумма` против `billing.Charges` (SQL-агрегаты), `Legacy` никогда не считается выставленным; суммы только при `finance.read` |

Интерфейс: Администрирование → Миграция — вкладки «Импорт», «Прогоны», «Сверка» (nb/en/ru, 360 px, клавиатура). Реальный импорт включается только после предпросмотра того же текста; `expectedSha256` защищает от подмены файла (409 `IMPORT_SOURCE_CHANGED`). Runbook: `docs/runbooks/16-migration.md` (границы импорта, процедура dry-run → real → повтор, freeze window, delta, сверка, go/no-go, отказ от переключения).

## Данные и обратимость

Миграция `ImportRuns` аддитивна (три новые таблицы, без триггеров; `CustomersDatabasePermissions`: приложению запрещены UPDATE/DELETE исходов и маркёра партии, DELETE прогонов). Откат приложения оставляет таблицы. Каждая партия имеет маркёр `ImportRunEntities` — **список для ручной компенсации**, не автоматический откат; разрушающего отката нет. Реальные файлы в репозиторий не добавляются. Внешних эффектов нет (внешние ID не записываются в связи интеграций — нет контракта, который позволил бы модулю Customers это делать без нарушения границ).

## Самопроверка и остаточные риски

Самопроверка, не независимая. Изменения существующих тестов объяснены: строка без названия теперь `Rejected MISSING_NAME`; неверный оргномер отклоняет строку (`INVALID_ORGNR`) вместо создания клиента без номера; повтор того же файла возвращает сохранённый результат; предупреждения имеют вид `Row N: CODE`. Поведение изменилось и в других импортах: неоднозначные слэш-даты в Licensing/Catalog теперь не угадываются (`MsBillingCsv` тихо использует вычисленный период); для импорта введён лимит `RateLimits:MigrationPerHour` (60, отдельно от экспорта).

Не сделано:
- Финансовая история и исторические PDF не импортируются: остаются в старой системе, происхождение помечается существующими `Legacy`/`Reconstructed`; решение о глубине миграции — EXT-01/EXT-09.
- Внешние ID не записываются в связи интеграций (границы модулей).
- Реальные источники и реальные файлы не видели: отображение колонок обобщённое, синонимы заголовков — как в `CsvTable`; после получения образца потребуется сверка отображения.
- Срок хранения таблиц прогонов не утверждён (предложение docs/04: 24 месяца после миграции; EXT-07/EXT-09).
- Проверка, что владелец соответствует утверждённой области клиентов, невозможна, пока область для клиентов не определена.

Итог **code_verified**; AC06 blocked (EXT-09), вопросы по AC05 и глубине AC02 — EXT-01. `accepted` не выставлен.
