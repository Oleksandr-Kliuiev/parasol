# ADR-017. Документ предложения фиксируется при выпуске и хранится один раз

Статус: принято для реализации DEV-08 (04.10.2026). Решение по сроку хранения документов — вместе с DEV-11 (retention); цифровая подпись и электронное принятие не вводятся без отдельного требования.

## Контекст

Аудит (A08): PDF формировался при каждом скачивании из текущих данных — реквизитов клиента и контакта, профиля ответственного, подвала шаблона по умолчанию и настроек компании. Неизменяемость строки предложения не делала неизменяемым документ: после переименования клиента, смены шаблона или обновления кода «скачанный после отправки» PDF отличался от отправленного, а вложение письма было отдельным рендером.

## Решение

1. **Снимок при выпуске.** Переход версии в Ready (submit без согласования или approve) в той же транзакции создаёт `sales.QuoteDocuments` (Preparing): JSON-снимок всех полей документа (продавец из `Sales:Company`, клиент и адрес, контакт, ответственный, язык, тексты, подвал и шаблон, позиции, цены, НДС, итоги, даты, срок) и его SHA-256, ревизию (1, 2… при повторном выпуске после правки), ключ объекта `quotes/{root}/{quote}/{document}.pdf`.
2. **Хранение один раз.** PDF рисуется из снимка и записывается в `IDocumentStore` только если ключа нет (Azure: `If-None-Match: *`; разработка и тесты — папка, `FileMode.CreateNew`). Документ становится Ready с SHA-256 и длиной в CAS-обновлении (`WHERE Status = Preparing`). Ключи не переиспользуются, повторная запись ключа оставляет первый объект и возвращает хэш его фактических байтов: SHA-256 в метаданных blob — только для эксплуатации, хранилище ему не доверяет (метаданные меняет любой с правом записи).
3. **Хранилище и БД — не одна транзакция.** Если запись не удалась, документ остаётся Preparing: скачать и отправить нельзя (409 `SAL_DOCUMENT_PREPARING`), `QuoteDocumentJob` (раз в минуту) и следующее обращение дописывают его из того же снимка. Если объект записан, а отметка Ready — нет (сбой между ними), повтор находит объект и принимает его как есть. Снимок фиксируется в БД до записи объекта, поэтому позднее завершение не берёт новых данных.
4. **Один объект для скачивания и письма.** Оба читают сохранённые байты и сверяют их SHA-256 с записью; расхождение или пропажа — ошибка `SAL_DOCUMENT_UNAVAILABLE`, ничего не отправляется. Ответ скачивания: `attachment`, `Cache-Control: no-store`, `nosniff`, ETag и `X-Document-Sha256/-Revision/-Origin`; `?revision=` отдаёт более раннюю ревизию той же версии.
5. **Доступ.** Только через API: `sales.read` и `finance.read`, права изменения не нужно. Контейнер `documents` приватный, у учётной записи хранилища выключены публичный доступ, публичная сеть и ключи доступа (нет SAS по ключу), worker получает роль только на этот контейнер; запись предложения ключ объекта не раскрывает.
6. **Неизменность в БД.** Триггер `trg_QuoteDocuments_Protect`: документ никогда не удаляется, Ready не меняется, Preparing меняется только на Ready с хэшем и длиной — для любой учётной записи, включая администратора. Роли приложения: DENY DELETE.
7. **Версии и мусор.** Новая версия предложения (revise) — новая строка и новый объект; старый объект не трогается. `QuoteDocumentJob.CleanOrphansAsync` (ежедневно) удаляет объекты под `quotes/`, на которые не ссылается ни одна запись и которые старше 7 дней; объект, на который ссылается документ (в том числе Preparing), не удаляется никогда. Объекты без записи появляются в основном после восстановления БД на более раннюю точку — на время сверки чистку останавливают (runbook 10).
8. **Наследие.** Миграция не перегенерирует старые документы. Версия, выпущенная до DEV-08, получает документ при первом обращении: Ready без отправки — Issued (выпускается сейчас), остальные — Reconstructed: снимок на дату восстановления, пометка на первой странице и в подвале каждой страницы, файл `…-gjenskapt.pdf`/`…-reconstructed.pdf`, отметка в UI. Сопоставление с вложением в «Отправленных» продавца не делается: автоматического законного доступа к ящикам нет.
9. **Рендер.** Собственный `PdfBuilder` (Helvetica, WinAnsi, nb/en) сохранён; версия рендера записывается в документ (`QuotePdf.RendererVersion`). Найдено визуальной проверкой и исправлено до первого сохранённого документа: таблица на страницах продолжения повторяет номер предложения, раздел и заголовки столбцов; длинное название позиции больше не обрезается многоточием, а заголовок, реквизиты клиента, значения справа (Deres referanse / Vår referanse) и подпись не выходят за свою колонку — всё переносится, слово длиннее строки разбивается у края; подвал сокращает свободный текст шаблона, чтобы номер страницы всегда помещался; ширина заменяемых символов (… – ’ “) считается по фактически выводимым.

## Проверка

- Логика выпуска, сбоев и доступа — интеграционные тесты на хранилище-папке с управляемыми сбоями (`QuoteDocumentsTests`).
- Реализация для Azure — те же операции против Azurite (эмулятор Blob REST API) в Testcontainers (`AzureBlobDocumentStoreTests`): однократная запись ключа, в том числе при восьми одновременных писателях, хэш по байтам при подменённых метаданных, список и удаление по префиксу, анонимный URL приватного контейнера (403), полный путь выпуск → скачивание → письмо → новая версия. Настройки учётной записи, которые есть только в Azure (без публичного доступа и ключей, роль worker на контейнер), проверяются тестами Bicep. Запись в настоящую учётную запись хранилища при реализации не выполнялась: это часть приёмки test-окружения после развёртывания (выпуск и скачивание тестового предложения).

## Последствия

- Скачанный после отправки PDF побайтно совпадает с отправленным при любых изменениях карточек, настроек и кода.
- Сбой хранилища задерживает отправку, но не выпускает предложение без документа.
- Резервное копирование включает контейнер `documents` (версии и мягкое удаление 30 дней включены) вместе с БД; восстановление одной БД без хранилища оставит записи без объектов — это обнаруживается проверкой хэша и runbook 10.
- Срок хранения документов и удаление по GDPR — решение DEV-11; до него документы не удаляются.
