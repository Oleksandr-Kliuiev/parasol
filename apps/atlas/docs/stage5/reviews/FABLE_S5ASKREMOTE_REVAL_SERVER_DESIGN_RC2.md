## Non-blocking findings (carry into briefs; exact file:line, trigger/impact, repair)

**NB1 — Evidence routine name collides with the accepted roles.sql prefix invariant.** `01_CONTROL_AND_IDENTITY.md:19` names `atlas_ask_remote_eval_snapshot`; `01:40-41` forbids prefix exceptions and requires the remote definer NOT to own it. `prisma/roles.sql:130-133` requires the count of `atlas_ask_remote_%` routines to equal the explicit list of nine, and `:391-436` moves every listed routine to the remote definer. Trigger: RS-A adds the routine under that name → provisioning fails, or the routine is listed and lands on the wrong owner. Repair: use a distinct prefix for all evidence routines (e.g. `atlas_reval_*`), add a separate exact allowlist/count for the evidence definer, keep the remote count at nine.

**NB2 — Placement of the table-owner DB login for PAUSE_EXPORT is implicit.** `06:57` (O→C, "existing owner DB routine"), `01:14`, `02:128-133`; `atlas_ask_remote_policy_revise` is executable only by the migration/table owner (`roles.sql:99,435`). Impact: if the long-lived controller C, which also serves I's IPC and the S bridge, holds that login resident, a defect in frame handling has table-owner reach (RLS and the "immutable registration" guards do not bind the owner; 01:101-104 admits the boundary). Repair: state that the table-owner credential is used only inside owner-initiated PAUSE_EXPORT/seed/registration operations through a short-lived owner-authenticated handle never resident in C's connection-serving state; the evidence-reader login is the only resident DB credential in C; add the negative to the Roles/RLS and Local-protocol acceptance rows (05:156,169).

**NB3 — Amendment 4 supersedes an RC6 sentence without naming it.** `03:93-118`, `README.md:46-47` vs `S5ASKREMOTE_REVAL_PLAN.md:53-54` ("время не подменяется в production-коде"; time-invariant expectations). Verified above: the frozen fixtures are not time-invariant under the real clock, so one norm must yield; the draft's gated, read-only, freshness-only reference is the sound choice versus mutating frozen bytes. Impact: `README:54-55` blocks implementation on unlisted contradictions; RS-B reviewers need the exact delta. Repair: cite the superseded RC6 lines in 03 (scope: registered synthetic sandbox only) and have the orchestrator record the delta in the next REVAL plan revision/manifest.

**NB4 — Case consumption before ARM/READY is stricter than the RC6 preflight rule; declare it.** `04:69-72` consumes the case before ARM_CASE/READY; RC6 `:236-238` says preflight unavailability leaves the case unconsumed. Ordering is the safe one (an armed slot can never exist for an unrecorded case), but ARM_UNAVAILABLE/SNAPSHOT_STALE/IPC_LOST after consumption burns a case with no submission; two such events in one 25-case group fail the run. Repair: state the supersession explicitly in 04 and require RS-C rehearsal evidence of arm-phase failure rate (consecutive arms without spurious failure) so fragility is measured, not assumed.

**NB5 — Process topology and peer-credential mechanism are deferred.** `01:65-70,74-78`, `06:10-16`. Node exposes no portable SO_PEERCRED/LOCAL_PEERCRED; on darwin a pure-JS adapter cannot verify peer PID/incarnation → IDENTITY stays UNVERIFIED (correct fallback) and RS-C/RS-D cannot claim a bound channel; who spawns I (it needs the operator TTY) and whether its two sockets are inherited or connected is unspecified, as is the instrument network-guard exception. Repair: RS-A brief pins the topology (C spawns S over an inherited socketpair; I either spawned by C with inherited FDs plus the operator TTY, or connects through a reviewed platform adapter), names the supported platform(s) for MEASURED, and keeps UNVERIFIED semantics as written.

**NB6 — Make post-authentication registration equality an explicit step-4 refusal.** `04:158-161`, `06:105`. A different actor/workspace bearer with a stolen session token passes the pre-auth claim; today the census (02:35-37) catches it only after a possible paid dispatch. Repair: add to step 4 "authenticated workspace/client/actor must equal the registration; otherwise fixed ASK_SCOPE_DENIED403 (or ASK_REMOTE_NOT_ADMITTED503) before phase1/reserve, arm consumed" and add it to the Registered-ingress acceptance row (05:166).

**NB7 — The 2 s end-to-end handoff deadline includes the instrument's durable PENDING save.** `06:220-221,232-233`, `04:228`. fsync+rename on I's journal, the server comparison, TRANSFER, validation, ACK and COMMIT share one 2 s window from the browser POST; a slow disk burns the one-use nonce → LOCAL_HANDOFF_UNVERIFIED, no credit. Repair (RS-C choice, no loosening of one-use/no-retry): require rehearsal evidence of save latency on the target platform, or bound POST→COMMIT server-side at 2 s while the browser's 204 simply waits.

**NB8 — Browser pairing-entry discovery is unspecified.** `04:28-29,78-79`. `AskCapabilityV2` is exact and cannot signal sandbox mode. Repair: state that the nonce entry exists only in the dedicated measured console build (RS-C sealed assets) as a plain manual control whose PAIR POST to an unregistered server yields ordinary 404; no capability DTO change.

Minor clarification (no action beyond wording): `02:136-137` "if it changed … refuse" should say whether an unrelated fence increment between commit and reread (e.g. a Connection trigger) refuses the receipt; reading the post-call fence/version inside the same pause transaction and using the reread only to confirm commit avoids a spurious CONTAINMENT_UNCONFIRMED in a quiescent sandbox.
