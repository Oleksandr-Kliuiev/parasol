## Optional notes (non-blocking precision an implementer would otherwise invent)
1. **02:41-43 raw classifier grammar.** State that the "client Ask POST shape" is `/clients/<one non-empty segment>/ask` under Express normalization (case-insensitive, optional trailing slash), independent of SCOPE_ID_PATTERN. A pattern-based classifier would let malformed IDs reach express.json and the controller (parser excerpt, second parse); Q2's malformed-ID 403 would catch it only late.
2. **02:168-169 AskAnswerV1.** Add a typed key table: focusObservationId string|null echo, generatedAt ISO-8601 UTC, intent for INSUFFICIENT = the supported intent, requestId = validated lowercase UUIDv4 echo, claim element exact keys with the seven claim codes enumerated once. This reduces ASK-A/ASK-B drift across separate sessions.
3. **02:69-70 vs 02:22/03:71.** Name the code for cap+1 overflow of people/devices/links/resources explicitly (ASK_TOO_LARGE 413 as "source cap" rather than ASK_SOURCE_INVALID). Both are audit-free fail-closed, but the browser message differs.
4. **03:96-103 rolling limit.** State where the 10 per 60 s check happens: at actor binding (pre-phase1) as well as at charge. With ≤1 owner per actor both are equivalent, but it decides whether a capped actor still pays a fence lock plus readiness query.
5. **03:112** "cannot reuse an uncertain connection" is unenforceable above Prisma's pool. Reword to "owner releases only after the transaction promise settles; connection hygiene is Prisma's, not claimed".
6. **02:63-69 items.** The bank never carries snapshot items; allow status derivation via `jsonb_typeof(items)='array'`/`itemCount` instead of materializing up to 100×1000 items under the 2 s phase1 budget, keeping "invalid item array → ASK_SOURCE_INVALID".
7. **Q2 (04:35) token rebinding.** Note the only reachable PG route: owner-session DELETE of the token row and INSERT of the same digest for another actor/workspace (fence increments; versions can be made to coincide cross-workspace). UPDATE-based moves are refused by AT002, so a reviewer should not expect that path.
8. **03:38-40 lock order.** Add the fixed mapping for 40P01/40001/P2034: phase1 → ASK_RUNTIME_NOT_READY, phase2 audit INSERT → ASK_AUDIT_FAILED. An Actor DELETE holding its tuple while waiting on the fence can deadlock with the audit FK KEY SHARE; Stage3 already accepts this class.
9. **02:13 observationId.** Give a charset (recommend the console ID pattern, 1..256). Today any ≤256 string is accepted and only yields "missing focus".
10. **03:128-132 browser.** State that Ask error treatment keys on HTTP status only (fixed messages for 400/401/403/404/409/413/429/503/504) and does not parse AskErrorV1, consistent with the console rule "never server bodies".
11. **02:139-142 mock matcher.** Specify NFC normalization and whitespace collapse before the case-insensitive compare, or state that only exact spacing matches.

## Assessment in the declared MOCK scope
- **Implementable: yes.** The HTTP/parser boundary, two-phase FOR SHARE admission, bank/projection, planner contract, compiler matrix, budgets and audit are all expressible with current primitives. The ASK-A module list (04:16-18) is cohesive and the only shared delta is the `main.ts` parser bootstrap with goldens.
- **Useful: as an engineering checkpoint only**, exactly as 01:22-25 states. The planner recognizes eight exact RU/EN phrases, so the free-text journey is honest but functionally a fixed-command surface. The durable value is the authority/evidence/citation/privacy substrate a future reviewed inference amendment would reuse.
- **Actual limitations.** No language understanding. No external inference and no path to enable it by flag or key (planner is private DI; OPENAI_* is bound only to Decisions). Phase budgets of 2+2+2+2 s consume the whole 8 s, so contention yields 504 by design. Capacity is per process, not distributed. FOR SHARE readers delay authority mutations and Stage3 admissions by up to 2 s each. No snapshot atomicity across queries; coverage says what was read.
- **Privacy/no-persistence.** Raw question stays in request memory and is never logged or audited. Audit metadata is five fixed keys and error bodies are three fixed keys. Browser uses no-store and no storage. Regex sanitization is correctly not claimed.
- **Tests.** Q1/Q2/Q4/Q6 are meaningful and PG-backed: parser goldens, fence contention, four-owner retention under ignored aborts, post-audit expiry rollback, and the LOW-focus/HIGH-other negative control. Restored-byte negative controls are required at acceptance.
