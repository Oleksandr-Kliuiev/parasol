## Required findings

### R1 — P1: Preserve authoritative terminal-fault metadata after revoking raw handoff

**Locations:** `04_TRANSIENT_HANDOFF.md:40–43`, `04_TRANSIENT_HANDOFF.md:98–111`, `04_TRANSIENT_HANDOFF.md:126–129`; the insufficient fallback schema is `05_PROOFS_AND_ACCEPTANCE.md:26–29` and `02_LEDGER_AND_CLOSURE.md:39–43`.

A policy pause revokes the pair and drops its raw slot. This is correct for raw-data access, but the only specified authenticated error-code transfer depends on that pair/current-authority handoff. PROCESS_CENSUS retains only `publication:'ERROR'`; SNAPSHOT has neither the detected circuit fault nor a public error code. A stored settlement outcome is not a complete substitute.

Concrete valid execution: the accepted service detects MODEL_MISMATCH, its settlement fails before recording the outcome, phase2 emits the fixed error, then the asynchronous durable pause commits before the operator's manual handoff click. The attempt remains EGRESS_COMMITTED with outcome null and its full reservation; the pair/slot has been revoked. The owner now receives only PAUSED, a full-reserve attempt and `publication:'ERROR'`. Those values cannot distinguish this mandatory TERMINAL_FAILED event from a generic error followed by an owner pause. The accepted implementation explicitly schedules this pause after publication (`packages/ask/remote/service.ts:157–175`); the manual click cannot reliably precede it. Upstream authentication faults also need differentiation from generic UPSTREAM_REJECTED outcomes. A lost/unknown settlement must not suppress a known stronger safety failure.

**Required repair:** specify a bounded, closed, safe terminal-observation record, generated by the measured original task and exported through the authenticated owner evidence channel independently of the raw browser slot. Bind it to the current arm/task/correlation/boot/registration and distinguish detected fixed safety/configuration fault, actual public outcome, and publication not completed. Preserve that metadata through pair revocation/raw cleanup until the POST census or terminal collection. Define retention, consumption and failure precedence; missing continuity remains UNKNOWN. Do not retain raw bodies, weaken the handoff's current-authority rules, treat an intended error as a delivered publication, or reconstruct dispatch/refund proof.

**Required verification:** model/tier, usage and upstream-auth faults with settlement failure/unknown commit; pause/revocation before the manual click; expiry/disconnect/unacknowledged handoff; fault followed by failed publication. A known authenticated safety fault must remain TERMINAL_FAILED with full/unknown liability, even when no raw handoff is allowed. Ordinary unavailable errors must retain their distinct incomplete classification.

### R2 — P2: Complete the closed local transfer and acknowledgement protocol

**Locations:** `01_CONTROL_AND_IDENTITY.md:73–77`, `01_CONTROL_AND_IDENTITY.md:111–116`, `04_TRANSIENT_HANDOFF.md:105–110`.

The common envelope says every listed `kind` selects an exact closed payload, but its enum has no transient-transfer kind. The handoff contract then requires delivery of browser values “together with the server's metadata binding and fixed verification result” and a safe acknowledgement without defining either exact object. No separate versioned transient frame is specified. FAILURE additionally refers to a sealed code list that is absent from the normative package. As written, an implementation must invent a new wire contract or violate the existing closed envelope. This is the remaining trust boundary between raw transient data and the receipt writer, not merely an internal naming choice.

**Required repair:** freeze the exact transient frame and acknowledgement schemas, either as a separate explicitly versioned protocol or as an explicitly separated allowed message kind. Specify required scalar bounds and binding fields for registration/boot/connection/pair/arm/case/fixture/policy/pre-snapshot/correlation, the exact request and response payload, sender/receiver authority, fresh challenge/sequence rules in both directions, and the one-use claim/transfer/ack/failure transition. State exactly which acknowledgement fields can enter safe persistence, what success means if delivery occurred but the acknowledgement was lost, and the fixed failure-code enum. Close the request shapes/direction permissions for owner-controller versus instrument operations rather than leaving the privileged command distinction to implementation convention. While freezing these schemas, distinguish monotonic event counters from the decreasing `activeTaskCount` gauge (`05_PROOFS_AND_ACCEPTANCE.md:22–24`).

**Required verification:** strict schema round-trips and unknown-key rejection; wrong arm/case/pair/boot and stale or replayed acknowledgements; delayed acknowledgements after timeout; reconnect; concurrent nonce claims; frame-size limits; instrument attempts to invoke owner mutation; proof that raw transfer objects cannot flow through the persistence schema. No automatic resend or Ask retry may result.
