### Required finding

**R1. The optional pre-initialized Connection step cannot be bound by the accepted command.** The provisioning section allows the owner-side setup transaction to initialize DISABLED, unbound pilot Connection rows and then says to bind them through the accepted private bind command. Those two steps are mutually exclusive in the current code. The bind service only creates a row with provenance and lifecycle version 1 in `packages/connections/connections.ts:123`. A pre-existing row with that ID produces a CONNECTION_EXISTS conflict, and a pre-existing row with the same tenant under another ID produces TENANT_ALREADY_BOUND. No accepted service ever sets binding provenance on an existing row, and the M365 authority refuses any connection without it with BINDING_PROVENANCE_MISSING at `packages/m365/authority.ts:48`. An owner-created unbound row is therefore a dead end whose only "repair" is an owner-side update of provenance, which the brief itself forbids as fabricated binding proof. Required change: remove Connection initialization from the setup transaction entirely. The pilot Connection row must be created solely by the bind command under the pilot operator, which also writes the connection.bound client audit row. The brief's "no upsert" and "never fabricate binding proof" rules then hold without exception. Scope of the change is text only; no code is affected.
