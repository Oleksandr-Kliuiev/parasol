# ADR-029 — финансовая сверка выбранной записи времени

Статус: локально принято в Parasol M26, 17 октября 2026. Публикации и развёртывания нет.

## Зачем

M24/M25 запрещают продолжать операцию при несогласованной истории банка или Billing.
Существующие LegacyCharges, миграционная сверка месячных сумм и карточка банка не
объясняют расхождение для одной выбранной записи времени. Сотруднику Finance нужны
проверяемые числа и ссылки на существующие документы, без автоматической правки истории.

## Граница чтения

`GET /api/v1/time/entries/{id}/financial-review` защищён отдельными AND-политиками
TimeRead, FinanceRead, ContractsRead, BillingRead и CustomersRead. Один список OR
дал бы лишний доступ. Сервис повторяет проверку до первого поиска данных. Обычный
ServiceLead или Sales не получает этот просмотр благодаря одному из своих разрешений.
Ответ — no-store. Ни суммы/ставки, ни внешние идентификаторы, ни сырой SourceId не входят
в DTO; чужой bank name не выдаётся за банк текущего клиента.

Имена клиента читаются до Time lease. Затем Shared M23 month admission и Time row lock
защищают выбранную запись от смешения двух её финансовых версий во время чтения.
Если организация изменилась между discovery и lock, возвращается существующий conflict.
Contracts и Billing читаются через contracts-only APIs. Новый Contracts API возвращает
лишь bank identity/organization/name/status/deleted, включая закрытые и удалённые банки.

Сервис не вызывает SaveChanges/commit, не создаёт period, audit, outbox, задания или
repair intent. Read transaction освобождается при возврате, ошибке и cancellation.
Это наблюдение связанных сохранённых фактов, не общий serializable снимок всех модулей
и не разрешение на последующее действие. Любая существующая команда сохраняет свои
M23–M25 guards; экран явно предлагает обновить сведения перед решением.

## Анализ

`FinancialReviewAnalysis` сопоставляет все source receipts префикса выбранного EntryId,
а не только доступный/активный банк. Полностью возвращённые старые утверждения не
считаются новым расходом. Остаток по банку сравнивается с текущими allocations; отдельно
выявляются незавершённая следующая approval, недоказанная история и потерянная/чужая
bank reference. Нельзя скрыть плохие receipts одним совпавшим суммарным числом.

Billing проверяется по точной allocation revision и source organization, включая
soft-deleted собственные allocations для распознавания старого snapshot. Частичный
экспорт объясняется отдельно; текущая запись не помечается Invoiced при просмотре.
Сохранённая ReviewNote остаётся видимой. Пустой список расхождений означает только,
что они не найдены в проверенных фактах одной записи, а не что проверена вся история.

`reviewOnly=true` в существующем Time list фильтрует сохранённые notes в SQL до totals
и cursor paging, сохраняя исходный employee scope. Он не является сканером неотмеченных
расхождений: вычисленная сверка запускается только для явно выбранной записи.

## Интерфейс и проверка

Finance открывает точный просмотр из строки времени, сравнивает ожидаемые/фактические
часы и переходит в имеющиеся bank/basis cards. Нет кнопок repair/approve/withdraw.
Новая загрузка скрывает старые факты; ошибка, отзыв прав и смена entry/user не оставляют
их на экране. Query keys включают сотрудника и EntryId, чтение отменяется при уходе,
долговременного кеша/автоматического retry нет. Подписи доступны на nb/en/ru.

DTO validator принимает GUID формата CRM, не только RFC UUID: `SequentialId.New`
кодирует SQL sort order без UUID version/variant markers. Отдельная регрессия защищает
этот формат. Контракт парсинга не импортирует React/UI permissions, чтобы оставаться
пригодным и для Node/browser fixtures без ослабления TypeScript конфигурации.

SQL сравнивает rowversions, balance, audit и outbox до/после повторных GET, проверяет
права, orphan/closed/foreign bank, старую billing revision, полную пагинацию фильтра,
technician ownership и cancellation настоящего SQL lock. Мобильный Axe/contrast/keyboard
сценарий использует синтетическую проекцию; критический staff workflow читает настоящий
report API в Chromium/Firefox/WebKit. Исходные финансовые записи автоматически не меняются.
