# DEV-22 Приёмка по ролям и параллельный месячный биллинг

Приоритет: **P1**. Аудит: **дополнительное направление целевого решения**.

Зависимости реализации: DEV-03, DEV-08, DEV-11, DEV-12, DEV-16, DEV-18, DEV-19, DEV-20. Проверки: Q3, Q5, Q6, Q7.

Внешняя приёмка: EXT-09, EXT-10.

## Контекст

Тесты подтверждают запрограммированные примеры, а реальный месячный процесс и обучение сотрудников ещё не проверены.

## Результат

Компания принимает рабочие сценарии и подтверждает каждую сумму пилотного месяца независимым расчётом.

## Объём реализации

1. Подготовить сценарии Sales, Technician, ServiceLead, Finance, Management/Admin с входными данными, ожидаемым результатом и протоколом замечаний.
2. Провести полный месячный цикл в параллель со старым способом: сбор, проверка, согласования, экспорт, счета/оплаты, продления, исключения и корректировки. Не отправлять клиентам два комплекта счетов.
3. Сверять по каждому клиенту/источнику/периоду: входные часы/подписки, расценки, proration, скидки, налоги, ручные правки, сумма и внешний документ.
4. Проверить хотя бы реальные применимые исключения: квартал/год, дочерний плательщик, пакет часов, середина периода, недоступный provider, спорный/кредитованный счёт.
5. Обучить новых пользователей по ролям; измерить время первого успешного самостоятельного сценария относительно цели ≤1 часа обучения.
6. Записать исходные бизнес-KPI: время месячного биллинга, доля ручных правок, необъяснённые расхождения, возраст ошибок, пропущенные продления и использование по ролям.

## Критерии приёмки

- **DEV-22-AC01** — У каждой роли есть заполненный протокол с исполнителем, датой, результатом и закрытыми блокирующими замечаниями.
- **DEV-22-AC02** — Полный месячный цикл завершён; одного успешного sandbox заказа недостаточно.
- **DEV-22-AC03** — 100% применимых оплачиваемых источников имеют объяснённый результат; необъяснённых расхождений сумм нет.
- **DEV-22-AC04** — Нет двойной отправки клиентам; пилотные references сопоставлены с реальными документами.
- **DEV-22-AC05** — Владелец каждого исключения и резервный ручной процесс определены; Finance подписал сверку.
- **DEV-22-AC06** — Если период ещё не завершён, задача остаётся code_verified/awaiting external gate, а не accepted.

## Данные и обратимость

Только выбранный пилотный scope; источник истины/право отправки счетов определяются до начала. Ошибочные внешние документы исправляются бухгалтерским процессом, а не удалением из CRM.

## Границы

Не сокращать месячный цикл до нескольких дней ради даты релиза и не выдумывать подписи пользователей.
