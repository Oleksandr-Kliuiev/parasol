# DEV-08 Фиксация отправленных коммерческих предложений

Приоритет: **P1**. Аудит: **A08**.

Зависимости реализации: DEV-00. Проверки: Q1, Q2, Q3, Q4.

Внешняя приёмка: не требуется отдельный внешний gate; нужны фактические локальные доказательства.

## Контекст

PDF берёт текущие реквизиты, owner и footer. Неизменяемость строки Quote не обеспечивает неизменяемость документа.

## Результат

Скачанный после отправки PDF совпадает с отправленным документом, даже после изменений карточек и обновления кода.

## Объём реализации

1. В момент release фиксировать все поля документа, включая компанию-продавца, адресата, контакт, владельца, язык, footer, шаблон, цены и период. Присвоить version/hash.
2. Хранить исходные PDF-байты в защищённом хранилище с immutable object key; локальный тестовый provider не требует Azure. В БД хранить manifest, hash, длину, media type, статус готовности и ссылку.
3. Продумать сбой между записью blob и DB: состояние preparation/pending, идемпотентное завершение, отсутствие отправки до ready. Не считать blob+SQL общей транзакцией.
4. Email attachment и download используют один зафиксированный объект. Загрузка только через авторизованный путь либо короткий scoped URL с корректными cache headers.
5. Для legacy предложений обозначить статус reconstructed/legacy, не выдавать пересозданный сейчас файл за исторический оригинал. Сопоставлять с ранее отправленным attachment, только если он законно доступен.
6. Обновить CLAUDE.md и спецификацию PDF после реализации; ограничение nb/en сохранить, пока отдельный Unicode-рендерер не обоснован.

## Критерии приёмки

- **DEV-08-AC01** — Изменение клиента, контакта, company settings и шаблона после release не меняет hash и байты PDF.
- **DEV-08-AC02** — Вложение письма совпадает с доступным для скачивания объектом.
- **DEV-08-AC03** — Сбой blob/SQL не выпускает предложение с отсутствующим документом и безопасно восстанавливается.
- **DEV-08-AC04** — Отсутствие finance.read либо права чтения конкретного предложения исключает доступ к его финансовому PDF по id или blob URL; право изменения для обычного скачивания не требуется.
- **DEV-08-AC05** — Новая версия не перезаписывает объект старой версии; orphan cleanup не удаляет referenced документы.
- **DEV-08-AC06** — Есть визуальная проверка длинного предложения на nb/en и многостраничного документа; не только проверка наличия PDF header.

## Данные и обратимость

Новая manifest-модель добавляется без перегенерации всех legacy документов. Бэкап/restore включает файлы и ключи; rollback не удаляет уже опубликованные объекты. Согласовать retention с DEV-11.
