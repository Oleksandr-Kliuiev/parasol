# DEV-15 Надёжные тесты и полное покрытие архитектурных правил

Приоритет: **P1**. Аудит: **A14**.

Зависимости реализации: DEV-00. Проверки: Q1, Q2, Q3, Q5.

Внешняя приёмка: не требуется отдельный внешний gate; нужны фактические локальные доказательства.

## Контекст

E2E параллельно выбирают один месяц. Projects/CustomFields отсутствуют в архитектурном списке. Coverage thresholds задекларированы, но не измеряются в CI.

## Результат

Тестовая система не даёт случайного зелёного/красного сигнала и охватывает каждый production-модуль.

## Объём реализации

1. Изолировать datasets по тесту/worker: отдельная БД/namespace периодов либо атомарный allocator. Не использовать неатомарное чтение свободного месяца; учесть два конкурентных CI runs и cleanup только своего scope.
2. Автоматически обнаруживать production module assemblies и contracts; добавить явную проверку полноты обнаружения. Projects/CustomFields должны участвовать в соответствующих применимых правилах.
3. Добавить совместимый с используемым Microsoft Testing Platform сбор покрытия. Проверять текущую поддерживаемую интеграцию по документации производителя при реализации; не копировать VSTest-флаги вслепую.
4. Измерить критический домен Billing/Contracts/TimeTracking: line coverage ≥90%, остальной backend ≥70% по NFR-10. Исключения для migrations/generated code документировать. Если baseline ниже — сохранить красный gate и задачи покрытия, не снизить порог молча.
5. Добавить набор инвариантов, негативных прав и конкурентности; проверки поведения важнее механического 100% строк.
6. Расширить браузерную матрицу Chromium/Firefox/WebKit для критических сценариев; определить реальное устройство/браузерное UAT, не называть эмуляцию iOS полноценным Safari acceptance.

## Критерии приёмки

- **DEV-15-AC01** — Два полных E2E-прогона с несколькими workers на чистых данных не имеют конфликтов периодов; retries не скрывают первый fail.
- **DEV-15-AC02** — Тест архитектурной полноты падает при добавлении нового модуля без включения в правила.
- **DEV-15-AC03** — CI публикует coverage с явным denominator и проваливается ниже требуемого порога.
- **DEV-15-AC04** — Регрессионные проверки четырёх финансовых дефектов проверяют инварианты и подтверждают исходные нарушения; прохождение этих проверок после исправления принимается отдельно в DEV-01/02.
- **DEV-15-AC05** — Критические сценарии проходят в Chromium/Firefox/WebKit; отсутствие browser runtime отражается как gap, а не pass.
- **DEV-15-AC06** — Тесты не используют реальные ключи поставщиков и не очищают чужую или рабочую БД.

## Данные и обратимость

Только тестовая инфраструктура/CI; случайные существующие бизнес-данные не изменяются. Изолированные базы удалять по собственному marker; не переименовывать общий crm database.

## Границы

Не увеличивать таймауты и число retries как основное исправление конфликта данных.
