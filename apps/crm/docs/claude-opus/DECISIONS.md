## Внешние gates

Машиночитаемое состояние — [external-gates.json](external-gates.json). Все начинаются с `not_run`. Один gate может иметь несколько проверок: `passed` разрешён только после всех перечисленных доказательств. Локальные завершённые части хранить в evidence соответствующей задачи.

| Gate | Что требуется для passed | Кто предоставляет подтверждение |
|---|---|---|
| EXT-01 | Утверждены DEC-01/02/08/09; Finance принял migration mapping и неоднозначные исторические начисления; назначены владельцы исключений. | PO, Finance, Sales, ServiceLead, operations |
| EXT-02 | В разрешённом реальном tenant проверены sign-in, assignment required, MFA/CA, доступы Graph, группы/PIM по применимости, отзыв роли/деактивация во всех репликах и без dev auth. Есть замер срока отзыва. | Tenant owner + security |
| EXT-03 | Разрешённые тестовые аккаунты реальных поставщиков; чтение, incremental sync, write ownership, timeouts/429, неизвестный результат отправки и поиск дубля; PowerOffice order/invoice/payment различены. Сохранены версии API/контракты и результаты. | Integration owner + Finance |
| EXT-04 | Реальное учение восстановления на Hostinger: snapshot restic из внешнего хранилища восстановлен на втором хосте (`deploy/hostinger/parasol.py restore`), согласованный возврат в работу из `deploy/hostinger/README.md` пройден (все записи остановлены, SQL, документы и ключи согласованы, privacy replay и restore reconciliation выполнены, внешние эффекты сверены), RPO/RTO измерены в пределах DEC-04. Ежедневная копия даёт RPO до 24 ч, поэтому цель DEC-04 подтверждается заново или копии делаются чаще. | Operations |
| EXT-05 | Полный профиль на согласованной конфигурации: 50 пользователей, p95, ошибки, ресурсы, SQL plans; 500 клиентов в биллинге; реальные ограничения экспорта документированы. | QA + operations + PO |
| EXT-06 | Независимый проверяющий провёл согласованный pentest/ASVS review; исправления перепроверены, открытых Critical/High нет, остальные риски явно приняты владельцем. Самопроверка автора не является независимой. | Security reviewer + PO |
| EXT-07 | Приняты retention/holds, порядок запросов субъекта, ограничения аудита, отдельная роль регламентного удаления, обработка копий и восстановлений; законность сроков проверена ответственным лицом. | Data owner + Finance |
| EXT-08 | Power BI Service выполняет scheduled refresh выбранным поддерживаемым способом, включая истечение/ротацию credentials и обновление следующих страниц/снимков. Локальный Power BI Desktop недостаточен. | BI owner |
| EXT-09 | Репетиция миграции на разрешённых данных, сверка количеств/сумм/истории, exception register, delta/cutover, время и безопасный rollback; владельцы данных приняли результат. | Data owners + Finance |
| EXT-10 | Приёмка по ролям, ручная доступность на реальных устройствах, обучение и полный месячный параллельный расчёт без повторной отправки реальных счетов; Finance подписал сверку. | PO + пользователи + Finance |
| EXT-11 | Выпуск на Hostinger проверен на деле: `main` защищена обязательной проверкой «Required checks» корневого `ci.yml` (правило ревью — по решению владельца), secret scanning и push protection включены, CODEOWNERS заведён; рабочая установка поднята оператором из выбранного коммита (`deploy/hostinger/parasol.py`), запись о выпуске (коммит, image IDs из manifest, backup перед обновлением) принята; импортированные Azure-workflows не включены; владельцы поддержки и выпускного решения назначены. | Repository owner + operations + PO |

Статусы gate: `not_run`, `in_progress`, `blocked`, `failed`, `passed`. Для passed обязательны owner, verified_at и evidence. Если блокер снят, повторить зависимые проверки. Gate не выдаёт сам по себе полномочия выполнить deployment: конкретное действие и среда должны быть разрешены владельцем.

## Условные расширения продукта

Не включать автоматически в текущую реализацию: несколько юрлиц и валют, Azure consumption и сложный CSP reconciliation сверх действующего объёма, shared mailboxes, электронная подпись, клиентский портал, AI-ассистенты. Прочитать существующую реализацию: уже имеющееся покрытие не удалять. Для нового объёма нужны сценарий, владелец, поставщик/лицензии, данные, отдельные карточки и AC. Если компания без функции не может работать, явно изменить release scope и оценку календаря; не объявлять продукт «полным» при исключении необходимого процесса.
