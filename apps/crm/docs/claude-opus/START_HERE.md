# Стартовое поручение для Claude Code Opus

Скопируйте текст ниже в Claude Code, открытый в корне полного репозитория.

---

Реализуй пакет доработок Vardahei CRM v2 из `docs/claude-opus/`, чтобы довести продукт до надёжной корпоративной CRM по направлению аудита от 03.10.2026. Нужны изменения кода, миграции, тесты и доказательства приёмки, а не новый общий план.

Сначала прочитай `CLAUDE.md`, `docs/claude-opus/README.md`, `EXECUTION.md`, `PROGRESS.md`, `backlog.json`, `DECISIONS.md`, `FINANCIAL_DESIGN.md` и `VALIDATION.md` в этой папке. Затем прочитай карточку первой доступной незавершённой задачи и релевантные исходники. Используй `execution_order` и зависимости; при первом запуске начни с DEV-00, затем DEV-15 и финансовых задач.

Работай последовательными проверяемыми изменениями. Для каждого задания: подтверди исходный дефект, реализуй решение, проверь критерии карточки, проведи самопроверку diff и миграций, сохрани evidence, обнови `acceptance.csv`, `backlog.json` и `PROGRESS.md`. После завершения переходи к следующей доступной задаче. Сохраняй модульную архитектуру, API-права, серверную защиту финансовых данных, i18n nb/en/ru и существующее поведение вне согласованных изменений.

Не считай старые тестовые результаты доказательством новой версии. Не закрывай требования заглушками, отключёнными тестами, сужением фильтров или ослаблением критериев. Не объявляй интеграцию проверенной только по mock. Для финансовых операций проверь повтор, конкуренцию, частичный сбой, восстановление и неизменяемость согласованной ревизии.

Сохраняй пользовательские файлы и текущие изменения. Если история Git отсутствует, выполни DEV-00 без массового добавления секретов и без потери рабочей копии. Разрешены локальные изменения, синтетические тестовые данные и изолированные тестовые среды. Это поручение не разрешает production deployment, реальные счета/письма/экспорт, удаление рабочих данных, изменение реального tenant или платных ресурсов. Для такого шага сначала подготовь конкретный результат и запроси только недостающий допуск с указанием среды и эффекта. Не спрашивай повторно то, что уже явно разрешено в текущей сессии.

При внешнем блокере зафиксируй точную причину и продолжай независимую локальную работу. Предложения в DECISIONS не выдавай за согласованные бизнес-правила. Не ставь `accepted`, пока не выполнены все AC и gates. Если сессия заканчивается, оставь воспроизводимое состояние в PROGRESS: изменённые файлы, реальные результаты проверок, незавершённые шаги и следующая задача. Итоговый ответ дай по-русски, код и комментарии — по правилам CLAUDE.md.
