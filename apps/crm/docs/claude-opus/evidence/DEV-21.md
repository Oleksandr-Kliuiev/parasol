- Дата: 05.10.2026. Исполнитель: Claude (Sonnet 5.5) и вспомогательные агенты той же сессии. **Это самооценка исполнителя, не независимая проверка и не пентест**; внешнее заключение — EXT-06.
- Исходная версия: `c16e86c` (DEV-20), ветка `codex/readiness`. Изменения DEV-21 закоммичены (сообщение «DEV-21: …», `git log codex/readiness`), без push; состав — [source-manifest.sha256](DEV-21/source-manifest.sha256).
- Стандарт: официальный CSV OWASP ASVS **5.0.0** с тега `v5.0.0` (`raw.githubusercontent.com/OWASP/ASVS`), скачан по явному согласию пользователя, SHA-256 `98c8fe91…cf680`, 346 требований (253 уровней 1–2; 92 уровня 3 не оценивались и перечислены в [matrix-summary.md](DEV-21/matrix-summary.md)). 2. **Исправления существенных находок** (все с тестами):
   - Открытый редирект после входа (`/%09/evil.com`, воспроизведён на уровне заголовка `Location`): единый валидатор `ReturnUrl`, проверка в login и в callback, таблица из 24 враждебных значений.
   - HSTS 1 год с поддоменами; cookie корреляции/nonce OIDC с префиксом `__Host-`; OpenAPI выключен по умолчанию, source maps выключены; `no-store` и CSP/`frame-ancestors` для `/api`, `/bff`, `/admin/jobs`.
   - Выход: `POST /bff/logout` выдаёт одноминутный билет, анонимный GET больше ничего не завершает; front-channel logout завершает только сессию по хэшу `sid`; деактивация завершает все сессии пользователя.
   - Прокси и хосты: `Forwarded:KnownNetworks` (по умолчанию частные диапазоны, в Bicep — подсеть приложений), `X-Forwarded-Host` только от известного прокси и из `AllowedHosts`; **Production не стартует с `AllowedHosts = *`** (значение теперь задаёт Bicep).
   - Токен-кэш MSAL шифруется (Data Protection); Hangfire-панель защищена antiforgery (POST без токена раньше возвращал 204); BI JWT: только RS256, только access-токены приложения, роли `Crm.Bi.*`; безопасное логирование отказов (401/403/CSRF/лимиты/BI) и аудит входа/выхода и чтения отчётов (без данных).
   - **Подтверждение личности для привилегированных действий (F-G2-08):** одной синхронизации каталога больше не достаточно — нужна свежая роль **и** интерактивная аутентификация (`auth_time`); `GET /bff/login?reverify=1` форсирует `prompt=login` и `max_age`, сервер сам проверяет `auth_time`, учётную запись и (если задано) `acr`; SPA предлагает «Подтвердить личность» без молчаливой потери несохранённых правок.
   - Бизнес-логика: роль без `finance.read` больше не затирает скрытые бюджет и сбор проекта (и себестоимость позиции прайс-листа без `finance.cost.read`); валидация длин, трёх стилей регулярок (`\z`), только http(s)-ссылки, нейтрализация CSV/Excel-формул, лимит и тип тела CSV-импортов (10 МБ, 415/413, лимит строк), реестр типов событий outbox, ссылки Graph только на тот же хост, https для адресов интеграций и белый список Teams, права на устаревшие mart-наборы, `RequiresFreshRoles` для индексации и активации прайс-листа, защита от подделки строк журнала, защита `rebase()` от `__proto__`, явный список эндпоинтов без права.
   - Инфраструктура и CI: алерт Sev1 на `AUDIT_INTEGRITY_MISMATCH` и на пропавшую контрольную точку, секреты Partner Center/Teams в Key Vault (только worker), проверка «не root» образа, dependency-review, ZAP baseline (только test, по расписанию), скан секретов в CI, `nuget.config` с сопоставлением источников, RSA-3072 для ключа Data Protection.
3. **Обновлённая модель угроз и документы** (AC06): `docs/06-security.md` (ASVS 5.0.0, границы оценки, модель угроз по списку из карточки, лимиты и реальные значения, статус находок), `SECURITY.md` (приём уязвимостей, предлагаемые сроки реакции — **требуют утверждения PO**, SSDF), runbook 17 (приём уязвимостей, пакет для независимого проверяющего, реестр исключений, повторная проверка), ADR-024 (инвентаризация криптографии), ADR-025 (инвентаризация журналирования), обновления ADR-019, runbook 12, docs/04, CLAUDE.md. ## Данные и обратимость

Две аддитивные миграции Identity: `SessionExternalId` (`ExternalSessionHash`) и `SessionAuthTime` (`AuthenticatedAt`), обе nullable, без триггеров. **Порядок развёртывания:** перед выкладкой выполнить `infra/entra/register-app.sh` (claim `auth_time`), задать `AllowedHosts` (Bicep делает это) и проверить адреса вебхуков Teams по белому списку — иначе привилегированные действия остаются закрытыми (отказ в безопасную сторону), а Production не стартует с `AllowedHosts = *` или не-https адресами интеграций. Откат приложения оставляет колонки; прежняя версия не знает про `auth_time`. Внешних необратимых эффектов нет.

## Самопроверка и остаточные риски

Самооценка, не независимая. Расхождения между отчётами об исправлениях и кодом, найденные при повторной оценке: `AllowedHosts: "*"` остаётся значением по умолчанию в `appsettings.json` (защищают проверка Production и Bicep); `Forwarded:KnownNetworks` не обязателен (частные диапазоны по умолчанию); F-G2-11 (login CSRF) не исправлен (только защита SPA от циклов); F-G2-03, F-G3-05, F-G3-10 исправлены частично; F-G5-02 подготовлен только в Bicep (нужна правка кода хостов для учётных данных экспортёра телеметрии).

Не сделано: список и завершение сессий пользователем/администратором (V7.x), `Clear-Site-Data` при выходе, закрепление базового образа по digest (решение в docs/06 §4: иначе замораживаются обновления безопасности), шифрование трафика между репликами, независимая проверка, реальный DAST, настройки репозитория GitHub (EXT-11), политика Conditional Access и PIM (EXT-02), решения по данным и срокам (EXT-07), утверждение сроков реакции на уязвимости (PO). Продуктовые решения без реализации: самоодобрение скидки по КП руководителем (F-G3-11), охват цепочки аудита (F-G5-14, нужен ADR), расхождения матрицы ролей docs/02 с `Permissions.cs` ([role-matrix-mismatches.md](DEV-21/role-matrix-mismatches.md)).

Итог **code_verified**; AC03 blocked (EXT-06), AC04 blocked (EXT-02). `accepted` не выставлен.
