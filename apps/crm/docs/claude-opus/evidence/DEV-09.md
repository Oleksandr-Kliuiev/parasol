## Подтверждённая проблема и реализация

**До** ([baseline-defect.txt](DEV-09/baseline-defect.txt)): `mine`/`MineOnly`, `ownerId`, `managerId` — фильтры, выбранные клиентом; `QuoteService.LoadAsync` и `ProjectService.LoadAsync` загружали любую запись по id; `TimeEntryRequest.ProjectId` сохранялся без проверки. Воспроизведено на `d53b3eb` во временном worktree: Sales B читает предложение Sales A по id, видит его в списке с `mine=false`, скачивает PDF и делает новую версию; техник, не назначенный на проект, открывает его, видит в списке и записывает на него часы — ответ называет проект.

**После** — модель [ADR-018](../../adr/ADR-018-record-scope.md):

- Права охвата в карте ролей `Permissions.cs`: `sales.quotes.all` (Admin, Management, Finance), `projects.all` (все роли, кроме Technician). Контракт `IRecordScope` (SharedKernel), реализация `RecordScope` (Infrastructure): `LimitedTo(permission)`; режим `Authorization:RecordScope` = `Restricted` по умолчанию / `Open`; параметр Bicep `recordScope` (`infra/env/*.bicepparam`, значение доходит до `Authorization__RecordScope`), предупреждение в журнале при `Open`.
- Sales: `QuoteService.InScope` (владелец текущей версии семейства) в списке и в `LoadAsync`, через который идут все 12 операций по id (карточка, PDF, правка, выпуск/согласование, отказ, отзыв, отправка, принятие, отказ клиента, отмена, новая версия, передача). Правила владельца: без `sales.quotes.all` владельцем можно назначить только себя (`SAL_QUOTE_OWNER_NOT_ALLOWED`), пропущенный `ownerId` в правке сохраняет владельца. `POST /quotes/{id}/transfer` (`sales.write`, `If-Match`, только текущая версия — `SAL_QUOTE_NOT_CURRENT`, активный пользователь — `SAL_QUOTE_OWNER_UNKNOWN`, 204), аудит смены владельца.
- Projects: `ProjectAccess.InScope` (руководитель, команда, исполнитель задачи) в списке, `LoadAsync`, удалении, `IProjectsApi.GetProjectAsync/GetProjectsAsync`. Таблица `projects.ProjectMembers` (миграция `20261004071249_ProjectMembers`, аудируемая, мягкое удаление, уникальность живой строки), `POST /projects/{id}/members`, `DELETE /projects/{id}/members/{userId}` (`projects.write`, идемпотентно), команда в ответе проекта.
- TimeTracking: проект записи — в охвате, той же организации, открыт (`TIM_PROJECT_NOT_AVAILABLE/_OTHER_ORGANIZATION/_CLOSED`); существующая привязка при правке не перепроверяется.
- Отчёт: `IRecordScopeReporter` (Sales, Projects), `GET /api/v1/admin/record-scope` (`audit.read`) — режим, роли «видят все» и «только свои/назначенные» (из карты ролей), записи по людям, без владельца/назначения, неактивные; страница «Администрирование → Доступ к записям».
- `/bff/user` — `recordScope { mode, allQuotes, allProjects }`. SPA: подсказки в списках, фильтр «только мои» скрыт там, где он ничего не меняет, поле владельца заблокировано для «только свои», диалог передачи (после передачи «за пределы охвата» — возврат к списку с уведомлением), раздел «Команда» на карточке проекта, страница отчёта; кэш запросов очищается при смене пользователя (запрос `/bff/user` при каждом возврате фокуса) и при выходе. nb/en/ru, коды ошибок, имена ролей.
- Документация: ADR-018 (матрица, пути, что не входит), [runbook 11](../../runbooks/11-record-scope.md), SEC-AZ-03, docs/02 §2 (BR-ACC-04) и §4.10, docs/03, docs/04, CLAUDE.md.

Изменённые и новые файлы: `src/BuildingBlocks/{Crm.Authorization/Permissions.cs, Crm.SharedKernel/Application/RecordScope.cs, Crm.Infrastructure/Security/RecordScope.cs, Crm.Infrastructure/DependencyInjection/ModuleRegistration.cs}`, `src/Hosts/Crm.Web/{Program.cs, Bff/BffEndpoints.cs, Http/RecordScopeEndpoints.cs}`, Sales (`QuoteService.cs`, `QuoteFeatures.cs`, `QuoteScopeReporter.cs`, `Domain/Quote.cs`, `SalesModule.cs`), Projects (`ProjectFeatures.cs`, `ProjectAccess.cs`, `ProjectScopeReporter.cs`, `Domain/ProjectMember.cs`, `ProjectsApi.cs`, `ProjectsModule.cs`, контракт, контекст, миграция и снимок), TimeTracking (`TimeEntryFeatures.cs`), `infra/{main.bicep, modules/apps.bicep, env/test.bicepparam, env/prod.bicepparam}`, web (типы, `AuthGate`, `AppShell`, `NoAccessPage`, router, quotes/projects страницы и api, `recordAccess/RecordAccessPage`, локали, фикстура тестов, 4 новых теста, `e2e/a11y.spec.ts`, `e2e/projects.spec.ts`), тесты (`RecordScopeTests` интеграционные и модульные, `InfrastructureTests`, `IntegrationTestHelpers`, изменения ниже), документы.

## Данные и обратимость

- Миграция `Crm.Projects/20261004071249_ProjectMembers` — только расширение (новая таблица, индексы, FK внутри схемы `projects`); существующие строки не меняются, назначения никому не раздаются. Релиз DEV-08 на новой схеме — E2E 54/54 ([лог](DEV-09/rollback-compat-d53b3eb.txt)).
- Перевод существующих данных: ничего автоматически — отчёт показывает предложения без владельца и с неактивными владельцами, проекты без назначений; владелец решает и исправляет через передачу и команды (runbook 11). Для окружения с данными до сверки — временный `Open` в `infra/env/<env>.bicepparam` (review), затем `Restricted`.
- Откат: `Open` возвращает прежнее поведение без изменения данных; откат кода до DEV-08 — штатный путь DEV-05, таблица команды остаётся неиспользуемой. `Down` миграции удаляет команды проектов — только вручную.
- Внешних эффектов нет.
- Нагрузка: охват предложений — коррелированный подзапрос по индексу `(RootId, VersionNo)`; проектов — `EXISTS` по индексам `ProjectMembers(UserId)`, `ProjectTasks(AssigneeId, Status)`, `Projects(ManagerId)`; роли с полным охватом получают прежние запросы без условий.

## Самопроверка и остаточные риски

Самопроверка (не независимое review): diff, все пути из карты (агент-разведчик прошёл модули, контракты, события, поиск, историю, custom fields, уведомления, экспорт и SPA), гонки добавления в команду (уникальный индекс, повтор — без изменений), устаревший `If-Match`, режим Open, системный пользователь worker.
