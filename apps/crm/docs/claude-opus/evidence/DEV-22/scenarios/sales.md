# Сценарии приёмки: Sales (продажи)

Статус документа: **шаблон сценариев, не результат**. Он не содержит исполнителей, дат, оценок и подписей. Результаты заносятся только в протокол ([protocol-template.md](../protocol-template.md)) настоящим исполнителем в среде `test` (EXT-10). Автоматические тесты ниже не заменяют UAT.

## 1. Назначение

Проверить, что продавец без подсказок разработчика проходит свой рабочий путь: лид, клиент, сделка, предложение со скидкой, версия предложения, договор, и видит только то, что ему положено. Особое внимание: деньги в предложении и договоре (BR-BIL-11, BR-SAL), границы охвата записей.

## 2. Предусловия

- Среда `test` с входом через Entra (не режим разработки). Тестовая учётная запись с приложением-ролью `Crm.Sales` из списка тестовых ролей [runbook 17 §4.2](../../../../runbooks/17-vulnerability-intake.md); для шагов с утверждением скидки и для негативных проверок нужны ещё учётные записи `Crm.Management` и `Crm.Finance` (тестовые, не личные учётные записи сотрудников). Создаёт владелец tenant (EXT-02), роли и сессии: [runbook 12](../../../../runbooks/12-roles-and-sessions.md).
- Учётные записи различаются по роли, не по человеку. Кто из сотрудников работает под какой учётной записью, записывается только в протоколе и только исполнителем.
- Интеграции: PowerOffice и Atera выключены или в демо; исходящая почта предложений выключена (`Sales:EmailEnabled` = false, `Integrations:MicrosoftGraph:MailEnabled` = false), чтобы шаг «Send» не уходил клиенту. Проверьте перед началом.
- Только синтетические клиенты и контакты. Реальные данные клиентов не вводятся.

## 3. Нужные данные

| Что | Откуда | Примечание |
|---|---|---|
| Номер организации (9 цифр, верная контрольная цифра) для нового клиента | Тестовый номер из набора разработчика или реестр Brreg в `test` | Записывается в протоколе как пример, не как реальная компания |
| Активный прайс-лист с 2 продуктами (месячная услуга, разовая работа) | Подготавливает Finance/Admin заранее | Продавец прайс-лист не создаёт: у Sales нет `catalog.write` |
| Лимит скидки по умолчанию | `Sales:DiscountLimitPercent` = 15 (по `appsettings.json`) | Фактическое значение окружения сверить с Admin |
| Вторая учётная запись `Crm.Management` для утверждения скидки | EXT-02 | Утверждает человек, не исполнитель-продавец |

## 4. Сценарии

### SAL-1. Лид становится клиентом со сделкой

| № | Действие (английские подписи интерфейса) | Ожидаемый результат |
|---|---|---|
| SAL-1.1 | Войти. На странице «My day» (`/`) найти блоки «My organizations», «Needs attention», «Quick actions». | Страница открывается без ошибок; блоки на английском; списки могут быть пустыми. |
| SAL-1.2 | Меню «Leads» (`/sales/leads`) -> «New lead». Заполнить Company, Contact person, E-mail, Source. Сохранить. | Сообщение «Lead created»; лид в списке со статусом «New». |
| SAL-1.3 | Открыть лид -> «Convert to customer»; в диалоге отметить «Also create a deal». | Сообщение «Lead converted»; появляется ссылка «Open customer»; статус лида «Converted». |
| SAL-1.4 | Перейти в «Open customer» -> вкладки «Overview», «Contacts», «Deals». | Клиент создан, контакт перенесён, во вкладке «Deals» есть сделка. |
| SAL-1.5 | Меню «Pipeline» (`/pipeline`). Найти сделку, «Move to <stage>» через меню «Actions for …». | Сообщение «Moved to …»; сделка в нужной колонке; «Weighted forecast» пересчитан. |
| SAL-1.6 | Попробовать «Mark as lost», выбрать причину, затем «Reopen». | Причина сохранена (например «Price»), сделка снова «Open». |
| SAL-1.7 | В списке «Organizations» воспользоваться поиском по имени и по номеру организации; при попытке создать клиента с тем же номером прочитать сообщение. | Показано «An organization with this organization number already exists» и ссылка «Open existing organization»; дубль не создан. |

### SAL-2. Предложение со скидкой

| № | Действие | Ожидаемый результат |
|---|---|---|
| SAL-2.1 | Меню «Quotes» (`/quotes`) -> «New quote» -> выбрать клиента, написать название. | Без клиента и названия — подсказка «Choose a customer and write a title first.»; после заполнения «Create quote» создаёт черновик (Draft). |
| SAL-2.2 | «Add line»: выбрать продукт «From price list», задать количество. Добавить разовую позицию. | Цена берётся из прайс-листа; итоги «Per month, excl. VAT» и общая сумма совпадают с ручным расчётом исполнителя (записать расчёт в протоколе). |
| SAL-2.3 | Задать скидку на строку выше лимита (по умолчанию 15 %). | Показано предупреждение «Above the <N> % limit»; зафиксировать, какое действие предлагается вместо «Release for sending» (отправка на согласование) и как оно называется на экране. |
| SAL-2.4 | Отправить на согласование. Затем под `Crm.Management` открыть предложение -> «Approve discount» (или «Reject» с причиной). | Статус «Awaiting approval», затем «Ready»; при отказе продавец видит «The discount was not approved: <причина>». Продавец сам утвердить скидку выше лимита не может (нет `sales.discount.approve`). |
| SAL-2.5 | В статусе «Ready» нажать «Download PDF». | PDF содержит все поля целиком (текст в столбцах переносится, не обрезается многоточием), номер, версию, суммы. Повторное скачивание даёт тот же файл (документ неизменяемый, DEV-08). |
| SAL-2.6 | «New version» (revise). | Создана версия 2 как черновик; версия 1 помечена «Older version». Номер общий. |
| SAL-2.7 | Довести версию до «Ready», нажать «Send» (если почта предложений выключена — убедиться, что отправка отклонена с понятным сообщением, а не молча ушла). | Ни одно письмо не ушло клиенту. Записать фактическое сообщение экрана (поведение при выключенной почте не проверено автором шаблона). Отправка допустима только на тестовый адрес исполнителя и только если окружение это разрешает. |
| SAL-2.8 | «Mark as accepted». | Статус «Accepted»; сделка получает связь; доступно «Create contract» / «Open the draft contract». |

### SAL-3. Договор из принятого предложения и проверка границ

| № | Действие | Ожидаемый результат |
|---|---|---|
| SAL-3.1 | «Open the draft contract» либо «Contracts» (`/contracts`) -> «New contract». Заполнить период, периодичность (Monthly/Quarterly/Yearly), «InAdvance/InArrears», строки. | Договор сохраняется как «Draft». |
| SAL-3.2 | Строка договора с частичным периодом (действует с середины месяца). | Договор сохраняется с датами действия строки. Правило пропорции BR-BIL-11 (цена за единицу умножается на долю, количество остаётся, в описании окно и доля вида `15/30`) проверяется в прогоне Finance (FIN-3); здесь фиксируются только входные даты и цена. |
| SAL-3.3 | «Activate». Затем «Give notice…» с датой, проверить срок уведомления. | Статус «Active» / «Notice given»; напоминание о сроке уведомления появляется в «My day» -> «Needs attention». |
| SAL-3.4 | Вкладка клиента «Licenses» и «Licenses» в меню. | Продавец видит подписки (у Sales есть `licensing.read`), но не может запустить импорт у дистрибьютора (нет `licensing.manage`). |

## 5. Денежные правила, которые проверяются

- Сумма строки = количество x цена x (1 - скидка %); итог предложения без MVA = сумма по строкам; месячная и разовая части разделены (`Monthly services` / `One-time items`).
- Пилотный пример приёмки (docs/02 §4.9): 5 000 + 25 x 250 + 3 ч x 1 250 = 15 000 NOK без MVA. Продавец проверяет только исходные цены в предложении и договоре; саму сумму основания проверяет Finance (сценарий FIN-2).
- Пропорция BR-BIL-11 и смена в середине периода (BR-CON-03): две части в сумме дают один период. Продавец готовит исходные данные, проверка суммы в прогоне — FIN-3.

## 6. Негативные проверки

Выведены из `src/BuildingBlocks/Crm.Authorization/Permissions.cs` (карта `ByRole`) на момент составления. Ожидание в колонке «Должно быть» — поведение кода; если оно расходится с docs/02 §2, это не ошибка исполнителя, а вопрос владельцу продукта ([role-matrix-mismatches.md](../../DEV-21/role-matrix-mismatches.md)).

| № | Проверка | Должно быть по коду | Примечание |
|---|---|---|---|
| SAL-N1 | Открыть предложение другого продавца по прямой ссылке `/quotes/<id>` | 404 как у несуществующего (охват записей, `sales.quotes.all` у роли нет) | Подтверждается тестами `RecordScopeTests`. «Только свои клиенты» (DEC-01) - **решение к подтверждению**: документ говорит о «своих клиентах» для биллинга и отчётов, код такого охвата не применяет |
| SAL-N2 | Утвердить скидку выше лимита | Кнопки «Approve discount» нет / действие отклоняется 403 | Нет `sales.discount.approve` |
| SAL-N3 | Открыть «Billing» (`/billing`) | Раздел виден (есть `billing.read`), прогоны читаются без охвата «свои клиенты» | Расхождение №4 в role-matrix-mismatches (документ: «R (свои клиенты)»); не утверждать, что охват есть. Решение DEC-01 к подтверждению |
| SAL-N4 | Кнопки «Collect», «Approve», «Send to PowerOffice» | Нет (нет `billing.manage`/`billing.approve`) | |
| SAL-N5 | «Catalog» -> создать продукт; правка прайс-листа | Недоступно (нет `catalog.write`) | Закупочные цены (cost) скрыты: нет `finance.cost.read`; «Margins» (`/reports/margins`) не показывается |
| SAL-N6 | «Administration»: «Users», «Audit log», «Integrations» | Не видны; прямой URL даёт «no access» | У Sales нет `audit.read`, `integrations.manage`; `users.read` есть (справочник ответственных) - раздел «Users» в меню зависит от `users.read`, фиксировать фактическое поведение, не предполагать |
| SAL-N7 | Сохранить изменение, которое кто-то другой уже изменил | Показаны обе версии, молчаливой перезаписи нет | покрыто автоматикой (см. ниже) |

## 7. Доступность и клавиатура

Проверить без мыши (Tab / Shift+Tab / Enter / Esc / стрелки), в светлой и тёмной теме, русском/норвежском/английском интерфейсе:

1. Skip link «Skip to content» первым Tab-ом доступен.
2. Форма нового лида и нового предложения: порядок фокуса логичен, пустое обязательное поле объявляется и связано с полем.
3. Закрытие диалога «Convert to customer» по Esc возвращает фокус на кнопку.
4. Выход из формы с несохранёнными изменениями спрашивает подтверждение.
5. Колонки pipeline и меню «Actions for …» доступны с клавиатуры; перемещение сделки не требует перетаскивания.
6. Поиск (глобальный) открывает контакт клавиатурой.
7. Масштаб 200 %: ни одна кнопка не теряется; на телефоне (≈360 px) список и форма читаются.
8. Скринридер (NVDA/VoiceOver) и реальные Safari/iOS/Android - только вручную (EXT-10); автоматика этого не проверяет.
