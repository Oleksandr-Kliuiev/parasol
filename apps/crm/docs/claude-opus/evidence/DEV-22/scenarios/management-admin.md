# Сценарии приёмки: Management и Admin (руководство и администратор CRM)

Статус документа: **шаблон сценариев, не результат**. Исполнители, даты, оценки и подписи не заполнены; результаты вносятся только в [протокол](../protocol-template.md) в среде `test` (EXT-10). Две роли описаны в одном файле, но имеют **разные протоколы и разных исполнителей**: Management и Admin - не одно лицо, а Admin с обоими правами утверждения не может подписать прогон за двоих.

## 1. Назначение

- **Management:** обзор компании, утверждение скидок, вторая подпись прогона выше порога, слияние дублей, чтение аудита, договоры и массовая индексация.
- **Admin:** пользователи и роли, интеграции (пауза, сопоставления), охват записей, пользовательские поля, шаблоны и этапы, миграция, приватность, режим обслуживания, фоновые задачи.

## 2. Предусловия

- Тестовые учётные записи `Crm.Management` и `Crm.Admin` ([runbook 17 §4.2](../../../../runbooks/17-vulnerability-intake.md)); вторые учётные записи `Crm.Sales`, `Crm.Finance`, `Crm.Technician`, `Crm.ReadOnly` и учётная запись без роли для негативных проверок. Роли назначает владелец tenant (EXT-02); порядок отзыва и сроков: [runbook 12](../../../../runbooks/12-roles-and-sessions.md).
- Привилегированные действия (утверждения, пауза интеграции, поля, удаление клиентов, режим обслуживания, privacy) требуют подтверждения ролей не старше 5 минут; при `AUTH_REVERIFY_REQUIRED` экран должен предложить подтвердить личность и вернуть на ту же страницу.
- **Опасные действия** (режим обслуживания, стирание персональных данных, реальная миграция, запись в PowerOffice) выполняются только в изолированной среде `test` с синтетическими данными и заранее согласованным окном. Не выполнять на среде с данными клиентов. Режим обслуживания останавливает запись для всех - предупредить остальных исполнителей UAT.

## 4. Сценарии

### MGT-1. Management: обзор, скидки, вторая подпись

| № | Действие | Ожидаемый результат |
|---|---|---|
| MGT-1.1 | «Dashboard» (`/dashboard`). | Плитки MRR, ARR, «Outstanding», «Overdue», «Weighted forecast»; «Invoiced per month»; «Renewals within 90 days»; «Hours this month». Исполнитель выбирает 3 числа и проверяет их по первичным экранам (договоры, счета, сделки); совпадение записать. |
| MGT-1.2 | «Quotes» -> предложение в статусе «Awaiting approval» -> «Approve discount» либо «Reject» с причиной. | «The discount is approved» / «The discount is rejected»; только после утверждения доступен PDF. |
| MGT-1.3 | «Billing» -> прогон -> блок «Approvals» -> «Approve as management» (после подписи Finance). | Подпись относится к текущей ревизии; если Finance потом меняет строки, подпись аннулируется с видимой причиной. Подпись того же человека, что подписал первым, не засчитывается. |
| MGT-1.4 | «Organizations» -> «Duplicates» (`/organizations/duplicates`): объединить пару и отменить объединение. | Слияние переносит договоры/предложения/банки часов; отмена возвращает; ссылки не теряются. |
| MGT-1.5 | «Audit log» (`/admin/audit`): найти действие из MGT-1.2 и MGT-1.3. | В записи: кто, когда, действие, объект; суммы в аудите финансовых модулей не редактируются и не удаляются. |
| MGT-1.6 | «Contracts» -> «Indexation»: только предпросмотр (без применения). | Предпросмотр показывает изменения; применение - решение Finance/Management в рамках процесса, не часть UAT. |

### MGT-2. Admin: пользователи, роли, охват, интеграции

| № | Действие | Ожидаемый результат |
|---|---|---|
| MGT-2.1 | «Administration» -> «Users» (`/admin/users`). | Список пользователей, роли, активность. Роли приходят из Entra и в CRM не назначаются вручную. |
| MGT-2.2 | Владелец tenant снимает роль у тестового пользователя (внешний шаг). Через ≤ 5 мин пользователь видит «No access». | Время от снятия до отказа записать (цель DEC-05 - не более 5 минут; **не вносить результат, пока он не измерен**). |
| MGT-2.3 | «Record access» (`/admin/record-access`). | Записать, что показывает экран (режим охвата записей Restricted/Open по `Authorization:RecordScope`). Режим Open - исключение окружения, не включать без решения DEC-01. |
| MGT-2.4 | «Integrations» (`/admin/integrations`): карточка PowerOffice -> «Приостановить»/pause с причиной; затем возобновить. | В журнале причина; задания записывают «Skipped»; исходящая очередь не отправляется ([runbook 05](../../../../runbooks/05-pause-integration.md)). |
| MGT-2.5 | «Mappings» (`/admin/mappings`): связать тестового клиента и продукт с записями PowerOffice (демо). | Связь создана; без неё основание получит аномалию. |
| MGT-2.6 | «Background jobs» (`/admin/jobs`): запустить `outbound-operations` вручную. | Очередь исходящих обрабатывается; результат виден в «Integrations». |
| MGT-2.7 | «Custom fields» (`/admin/custom-fields`): определить поле клиента; ответить на него на карточке клиента. | Поле появляется на карточке; значение сохраняется; определять поля вправе только Admin. |
| MGT-2.8 | «Pipeline stages», «Quote templates», «Technicians» (`/admin/pipeline`, `/admin/quote-templates`, `/admin/technicians`). | Переименование этапа и правка шаблона сохраняются; изменённые тексты видны в новых, но не в уже выпущенных PDF. |

### MGT-3. Admin: миграция, приватность, обслуживание (только изолированная среда)

| № | Действие | Ожидаемый результат |
|---|---|---|
| MGT-3.1 | «Migration» (`/admin/migration`): загрузить синтетический файл -> «Check» (dryRun). | Показаны счётчики created/updated/unchanged/conflicts/rejected и коды причин; ничего в клиентов не записано ([runbook 16](../../../../runbooks/16-migration.md)). |
| MGT-3.2 | Реальный импорт на тестовой копии, повтор того же файла. | Счётчики равны предпросмотру; повтор возвращает сохранённый результат и ничего не пишет; различие значения - конфликт, значение CRM остаётся. |
| MGT-3.3 | «Personal data» (`/admin/privacy`): новое обращение по синтетическому контакту, экспорт данных. | Экспорт содержит данные контакта; стирание (необратимо) выполнять только на синтетическом контакте и только по решению владельца сценария ([runbook 13](../../../../runbooks/13-personal-data.md)). |
| MGT-3.4 | «Maintenance» (`/admin/maintenance`): включить режим только для чтения с причиной, проверить запись другой учётной записью, выключить. | Все записи отклонены, чтение работает; в журнал аудита попадают включение и выключение; войти могут только держатели `operations.maintenance`. **Предупредить остальных исполнителей.** |
| MGT-3.5 | Мониторинг: «Integrations» -> раздел исключений: назначить владельца и статус (Open/InProgress/Resolved) для тестового исключения. | Назначение сохраняется с проверкой версии (If-Match); см. [runbook 15](../../../../runbooks/15-monitoring.md). Реальные получатели оповещений - EXT-01, не придумывать адреса. |

## 5. Денежные правила, которые проверяются

- **BR-BIL-04:** порог второго утверждения - строго больше 200 000 NOK без MVA на основание; ровно 200 000 не превышает; два разных активных человека в любом порядке; Admin с обоими правами исключением не является; подписи привязаны к ревизии содержания.
- **BR-SAL-05:** скидка выше лимита роли требует утверждения Management; документ создаётся только после него.
- Неизменяемость аудита финансовых модулей и утверждённых оснований: никакая роль, включая Admin, не удаляет и не переписывает их через интерфейс.
- Admin не должен «автоматически» обходить запрет чтения стоимости: в коде Admin получает все права, включая `finance.cost.read`; **политика Admin и стоимости - вопрос DEC-01** и здесь не утверждается.

## 7. Доступность и клавиатура

1. Дашборд: проверить, есть ли у диаграммы «Invoiced amount per month» текстовая альтернатива или таблица значений (наличие не проверено автором шаблона - записать факт); плитки читаются скринридером.
2. Админ-таблицы (пользователи, журнал аудита, интеграции): фильтры, пагинация («Load more», «Showing N of M») с клавиатуры.
3. Диалоги паузы и режима обслуживания: причина обязательна, ошибка связана с полем, фокус возвращается.
4. Подтверждение личности (`AUTH_REVERIFY_REQUIRED`) возвращает на ту же страницу; адрес возврата не может вести на чужой сайт.
5. Мобильный размер: админ-экраны миграции вмещаются в телефон.
6. Скринридер и реальные устройства - вручную (EXT-10).
