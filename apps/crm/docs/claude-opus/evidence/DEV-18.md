## Что найдено и сделано

Проход по сценариям Sales / Technician / ServiceLead / Finance и по ошибочным состояниям дал следующие разрывы; каждый закрыт кодом и тестом.

| Находка | Было | Стало |
|---|---|---|
| 412 в четырёх формах (организация, договор, продукт, контакт) | Кнопка «Reload» молча стирала правки пользователя | `ConflictBar`: читает последнюю версию, показывает поля, которые изменили обе стороны (значения «у вас»/«у них»), и поля, изменённые только другой стороной. Два явных выхода: «Оставить мои изменения поверх последней версии» (ничего не сохраняется до нового нажатия «Сохранить») и «Отказаться от моих». Общий код в `web/src/shared/forms/` |
| Несохранённые правки | Уход со страницы (ссылка, «Отмена», закрытие вкладки) терял форму | `useUnsavedChanges` + `UnsavedChangesDialog`: диалог, «остаться» возвращает фокус на элемент, с которого начался уход; `beforeunload` для закрытия вкладки; после успешного сохранения вопроса нет |
| Нет соединения | TanStack Query **приостанавливал** мутацию без сообщения и отправлял её позже, при возврате сети (повторное нажатие отправляло дважды) | `networkMode: 'always'` для запросов и мутаций: ошибка видна сразу — «Нет соединения… ничего не отправлено» |
| 429 | Только экспорт организаций знал о лимите, без времени ожидания | `ApiError.retryAfterSeconds` из `Retry-After` (секунды или дата); общий текст «Повторите через N с» |
| Запрос без ответа | Бесконечное ожидание | Таймаут 60 с → `RequestTimeoutError` → «Сервер слишком долго отвечал. Изменение могло сохраниться: проверьте запись» (исход неизвестен, текст этого не скрывает) |
| Долгий экспорт биллинга | Одна ошибка опроса заменяла страницу прогона страницей ошибки; прогресса не было | Строка состояния «Отправка в PowerOffice: отправлено X, с ошибкой Y, из Z», время обновления (Europe/Oslo), «Обновить сейчас», пояснение «можно покинуть страницу, дублей не будет»; сбой обновления — предупреждение с последним состоянием, страница остаётся |
| Сделка без следующего шага | Задачи видны только в таймлайне внизу страницы | `NextStep` на открытой сделке: ближайшая открытая задача, ответственный и срок (просроченная — красным), «ещё N», либо «следующего шага нет» с кнопкой добавления |
| Сохранённые представления | Были только в мониторинге, формат без версии | `SavedViews` (`web/src/shared/views/`): имя + фильтры из адреса; версия формата 1, лимит 10 представлений/40 символов/200 символов значения, белый список ключей каждой страницы, ключ на пользователя; чужой/старый/повреждённый формат сбрасывается с объяснением; отказ хранилища сообщается. Подключено: организации, договоры, лицензии, воронка, проекты, счета |
| Длинные имена, узкие экраны | Карточка организации с длинным именем без пробелов давала горизонтальную прокрутку 560 px на 320 px; 11 вкладок организации — до 1007 px; поле поиска каталога и `minmax(320px,…)` сетки ломали 320 px | `overflow-wrap: anywhere` для заголовков/ссылок/списков в `main`; полоса вкладок прокручивается сама; сетки `minmax(min(Npx, 100%), 1fr)`; поле поиска `width:100%; max-width:320px` |

Сохранённые представления хранят только фильтры; права на записи проверяет сервер при каждом чтении, локально ничего не является источником прав. Финансовых значений и курсоров в представлении нет (ключи — белый список).

## Запуски

Из `web/`:

- `npm run lint`, `npm run typecheck` — без замечаний.
- `npm test` (vitest, 2 worker): 28 файлов, 105 тестов, все прошли. Новые: `shared/forms/diff.test.ts`, `shared/views/store.test.ts`, `shared/utils/errors.test.ts`, дополнения `api/client.test.ts` (Retry-After секундами и датой, таймаут, отмена вызывающим).
- `npm run build`: initial total 288,4 KB (бюджет 300 KB).
- `npm run e2e` на пересозданной базе и свежих хостах — см. [e2e.txt](DEV-18/e2e.txt).

Сбои по ходу работы (исправлены): фокус не возвращался после «Продолжить редактирование»; отсутствие сообщения при отключении сети (причина — пауза мутаций TanStack Query); горизонтальная прокрутка на 320/640 px (см. таблицу); тест клавиатуры в Firefox/WebKit (ограничен Chromium, причина выше). Один промежуточный прогон на долгоживущих хостах упал на `privacy.spec` в трёх браузерах из-за лимита экспортов (`RateLimits:ExportsPerHour = 10`, счётчик накопился за много повторных запусков); после перезапуска хостов тесты прошли, итоговый прогон выполнен на свежих хостах.

## Данные и обратимость

Схема, API и миграции не менялись. Сохранённые представления — localStorage браузера, формат версии 1; представления старого формата (без `version`, например из мониторинга) сбрасываются с пояснением, а не интерпретируются. Откат: прежняя сборка SPA не читает ключи `crm.views.*`, ничего не ломается; ключи старого мониторинга (`crm.monitoring.views.*`) не затронуты. Внешних эффектов нет.

## Самопроверка и остаточные риски

Проверены diff, пути ошибок (412, 429, таймаут, офлайн, отмена, повторное нажатие), права (представления не хранят данных), три локали. Самопроверка выполнена исполнителем, независимого review нет.

Не сделано / ограничения:
- UAT сотрудников каждой роли, ручной проход скринридером, реальные Safari/iOS/Android — EXT-10 (PO / пользователи / Finance), владелец не назначен.
- «Оставить мои изменения» подключено в четырёх основных формах (организация, договор, продукт, контакт). Остальные диалоги (например, строки основания биллинга, активности) используют прежнюю обработку 412 с перечитыванием — не расширено.
- Дата/время в диалоге задачи (`datetime-local`) интерпретируется в часовом поясе браузера, а не Europe/Oslo; для сотрудников вне Норвегии срок сдвинется. Не исправлено, нужен продуктовый выбор (DEC).
- Сохранённые представления не синхронизируются между устройствами и не привязаны к серверу (осознанно: без новой схемы).
- Таймаут 60 с общий для JSON-запросов; долгие операции должны быть асинхронными (как экспорт биллинга). Скачивание файлов (`download`) таймаута не имеет.

Итоговый статус **code_verified**; AC01 blocked (EXT-10), AC02/AC05 дополняются ручной проверкой EXT-10. `accepted` не выставлен.
