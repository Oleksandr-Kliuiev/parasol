# Runbook 14. Power BI: чтение CRM и плановое обновление

Когда: подключение нового отчёта Power BI к CRM, ротация учётных данных BI-приложения, обновление не проходит. Модель — [ADR-022](../adr/ADR-022-bi-read-api-and-snapshots.md). Владелец BI и решение о способе — DEC-06, приёмка планового обновления — **EXT-08**.

**Что доказано, а что нет.** Код проверяет токен, права наборов, страницы, снимки и определения (интеграционные тесты DEV-14). Что Power BI **Service** без браузера обновляет отчёт этим способом, в том числе после истечения исходного токена, подтверждает только EXT-08 в реальном tenant. До этого способ ниже — рекомендация.

## 1. Что подключается

Не cookie, не личный токен и не SQL. Приложение Entra (BI-клиент) получает токен для CRM и читает `https://<crm>/api/v1/bi/v1`:

| Путь | Что отдаёт |
|---|---|
| `GET /` | наборы с колонками и типами, ключи, определения, глоссарий |
| `GET /datasets/{набор}?from=&to=&pageSize=&cursor=` | страницы набора за период (по умолчанию 12 месяцев) |
| `GET /snapshots/{набор}?month=yyyy-MM&revision=` | снимок закрытого месяца |

Каждая страница: `schemaVersion`, `asOf`, `columns[{name,type}]`, `rows` (массивы в порядке колонок), `nextCursor`; на последней странице `watermark` (= `asOf` начала обновления). Обновление идёт, пока есть `nextCursor`, и **всегда читает период заново**: строка, появившаяся во время чтения, попадёт в следующее обновление.

## 2. Наборы и права

| Набор | Роль приложения |
|---|---|
| `organizations`, `revenue-by-month`, `revenue-by-customer`, `hours-by-customer`, `subscriptions`, `renewals`, `recurring-revenue`, `invoices` | `Crm.Bi.Read` |
| `microsoft-costs`, `margins` | `Crm.Bi.Cost` |

Колонки и их типы — в каталоге (`GET /`). Новые колонки приходят с новой `schemaVersion`; отчёт на прежней версии продолжает читаться в переходный период. Предложений и проектов в наборах нет.

## 3. Определения

- **MRR** — месячная стоимость действующих строк договоров на дату, NOK без НДС (квартальные и годовые строки разделены на месяцы). Это не выставленная выручка.
- **ARR** — MRR × 12 на ту же дату.
- **Утверждённая сумма (`approvedExVat`)** — содержимое утверждённых оснований; после утверждения неизменно. **Ожидающая (`pendingExVat`)** — что выставили бы собранные, но не утверждённые основания.
- **Выставлено** — `totalIncVat` счёта в учётной системе. **Остаток (`outstanding`)** — что учётная система показывает неоплаченным на момент `asOf`. Колонки «оплачено» нет: остаток падает и при оплате, и при кредит-ноте, CRM их не различает. Оплату читайте в PowerOffice.
- **Маржа** — утверждённая выручка минус затраты Microsoft минус часы по внутренней часовой стоимости (`hourlyCostUsed` в каждой строке). Себестоимость оборудования в CRM не ведётся; `costIncomplete` — лицензии выставлены, затрат Microsoft нет.
- **Снимок месяца** — таблица, как она была прочитана после закрытия месяца; `provenance`: `Captured` (не позже 5 дней после конца месяца) или `Reconstructed` (собрано позже из текущих данных, не состояние на конец месяца).

## 4. Подключение (один раз)

1. Владелец tenant регистрирует приложение «Vardahei CRM BI (<env>)» и выдаёт ему роли приложения **CRM BI read** (и при необходимости **CRM BI cost**) на приложении CRM (`infra/entra/register-app.sh` описывает роли; скрипт запускает владелец tenant, не разработка). Аутентификация приложения — **сертификат** из Key Vault владельца BI; секрет в репозиторий и в отчёт не помещается.
2. В окружении CRM задать (конвейер, `infra/env/*.bicepparam`): `CRM_BI_ENABLED=true`, `CRM_BI_AUDIENCE=<идентификатор приложения CRM, aud токена>`, `CRM_BI_CLIENTS=<application id BI-клиента>[,…]`. Пустой список клиентов не пускает никого; включённое API без tenant, audience и клиента не запускается.
3. Получить токен (client credentials, область `<audience>/.default`) и проверить `GET /`: ответ 200 и список наборов по ролям. Токен другого tenant, не для CRM, просроченный или приложения вне списка — 401/403.

## 5. Плановое обновление

Способ выбирает владелец BI (DEC-06) и проверяет в EXT-08. Две схемы, обе читают это же API:
- **Коннектор Power BI с OAuth приложения** (клиентские учётные данные, обновление токена средствами сервиса): набор читается постранично, цикл по `nextCursor`.
- **Управляемая выгрузка:** задание в Azure (Data Factory, Logic App, Function с управляемой identity) читает наборы и кладёт файлы туда, откуда Power BI читает без браузера. Выгрузка — не обход: права и определения те же.

Пример запроса Power Query. Токен в запросе не хранится: `GetToken` — функция владельца BI, которая обращается к Entra с сертификатом или к его хранилищу секретов.
```m
let
    Base = "https://<crm>/api/v1/bi/v1/datasets/revenue-by-month",
    Page = (cursor as nullable text) =>
        let
            Url = Base & "?from=2025-01-01&pageSize=1000" & (if cursor = null then "" else "&cursor=" & Uri.EscapeDataString(cursor)),
            Body = Json.Document(Web.Contents(Url, [Headers = [Authorization = "Bearer " & GetToken()], ManualStatusHandling = {401, 403, 429}]))
        in Body,
    Pages = List.Generate(
        () => Page(null),
        each _ <> null,
        each if [nextCursor] = null then null else Page([nextCursor]),
        each [rows]),
    Rows = List.Combine(Pages)
in
    Rows
```
`GetToken` не входит в репозиторий. Имена полей — в `columns` первой страницы.

**Проверка EXT-08** (владелец BI, реальный tenant). Плановое обновление:
- выполняется без браузера и без человека;
- проходит после истечения первого токена (≥ 1 час) и после ротации сертификата;
- при 429 (лимит 120 запросов в минуту на приложение) повторяет запрос;
- в отчёте все страницы, а число строк равно числу в источнике.

Результат и скриншоты без данных клиентов — в evidence DEV-14.

## 6. Снимки закрытых месяцев

- Ежедневно в 05:10 (Осло) задача `reports-snapshot` берёт снимок прошлого месяца для наборов, у которых его нет. Месяц без снимка можно взять вручную: Finance — `POST /api/v1/reports/snapshots/{yyyy-MM}` с причиной (право `finance.cost.read`).
- Первый снимок месяца остаётся. Исправление — новая ревизия: `{"reason": "…", "revise": true}`; прежняя читается по `revision`.
- Отчёты закрытого месяца читают `/snapshots/…`, а не живые наборы. Для месяцев до DEV-14 снимки `Reconstructed`: ориентир, не бухгалтерский факт.
- Целостность: чтение проверяет SHA-256; при несовпадении снимок не отдаётся (`RPT_SNAPSHOT_CORRUPT`). Объект возвращают из версий blob ([runbook 10](10-quote-documents.md), soft delete 30 дней).

## 7. Если обновление не проходит

| Ответ | Причина | Что делать |
|---|---|---|
| 401 | токен просрочен, чужой tenant, не для CRM, подпись | получить токен заново; сверить audience и tenant |
| 403 `BI_DATASET_FORBIDDEN` | роль без прав на набор | выдать `Crm.Bi.Cost` для затрат и маржи |
| 403 без кода | приложение вне `CRM_BI_CLIENTS` или без роли | добавить клиента в список (через конвейер), проверить роль |
| 429 | больше 120 запросов в минуту | увеличить `pageSize` (до 5000) или сделать паузы |
| 400 `BI_CURSOR` | курсор не от этого API | начать обновление сначала |
| 404 `RPT_SNAPSHOT_NOT_FOUND` | снимка месяца нет | дождаться задачи или взять снимок вручную (§ 6) |
