# Runbook 10. Документы предложений: «сохраняется», ошибки чтения, восстановление

Когда: на карточке предложения висит «Документ этой версии сохраняется», скачивание отвечает `SAL_DOCUMENT_PREPARING` или `SAL_DOCUMENT_UNAVAILABLE`, в журнале worker есть «could not be stored yet» или «Removed stored object», либо БД восстанавливали из резервной копии. Модель — [ADR-017](../adr/ADR-017-quote-documents.md).

Роли: **Admin CRM**; для хранилища — администратор Azure (роль на учётную запись хранения окружения).

## 1. «Сохраняется» дольше пары минут
Документ выпущен (все поля зафиксированы), но PDF не записан в контейнер `documents`.
1. Проверьте журнал crm-worker: `traces | where message has "could not be stored yet"` — причина (сеть, права identity, недоступность хранилища).
2. Права: identity worker должна иметь `Storage Blob Data Contributor` на контейнер `documents`, identity web — на учётную запись (Bicep `data.bicep`).
3. После устранения причины ничего вручную делать не нужно: задача `quote-documents` (раз в минуту) допишет документ из снимка; можно запустить её сразу в «Интеграции → Фоновые задачи». Предложение до этого не скачивается и не отправляется — так задумано.

## 2. `SAL_DOCUMENT_UNAVAILABLE`
Объекта нет в хранилище или его SHA-256 не совпадает с записью. Ничего не отправлялось.
1. Найдите запись: `SELECT Id, QuoteId, Revision, ObjectKey, ContentSha256, Length FROM sales.QuoteDocuments WHERE QuoteId = '<id>' ORDER BY Revision;`
2. Проверьте объект в контейнере `documents` по `ObjectKey` (версии blob включены: перезаписанный или удалённый объект восстанавливается из предыдущей версии/мягкого удаления в течение 30 дней).
3. Восстановленный объект должен дать тот же SHA-256, что в записи; иначе это инцидент целостности (runbook 06) — запись не правится (триггер это запрещает), новый документ не «подкладывается».

## 3. После восстановления БД из резервной копии
Записи и объекты восстанавливаются отдельно.
1. **До** запуска worker отключите очистку: в Hangfire приостановите `quote-document-orphans` (или не запускайте её до сверки). Объекты, созданные после точки восстановления, не имеют записей и иначе будут удалены через 7 дней.
2. Сверьте: записи без объектов (`ReadAsync` → `SAL_DOCUMENT_UNAVAILABLE`) восстанавливаются из версий blob; объекты без записей — документы, выпущенные после точки восстановления. Их предложения в восстановленной БД снова в состоянии до выпуска; выпуск заново создаст новый документ (новый ключ), а осиротевший объект — свидетельство того, что было отправлено (если было). Решение, хранить ли его, — за владельцем (DEV-11).
3. Включите очистку после сверки.

## 4. Документ «воссоздан»
Версии, выпущенные до DEV-08, не имеют сохранённого оригинала. При первом скачивании или отправке создаётся документ: ещё не отправленная версия — обычный выпуск; остальные — «Gjenskapt kopi / Reconstructed copy» с пометкой на каждой странице и в UI. Не выдавайте такую копию за отправленный документ; оригинал, если он нужен, — во вложении письма в «Отправленных» продавца.

## 5. Что нельзя
- Менять или удалять строки `sales.QuoteDocuments` (триггер вернёт 51011) или объекты под `quotes/` в контейнере вручную.
- Включать публичный доступ к контейнеру или выдавать SAS: документ доступен только через приложение с проверкой прав.
- Направлять два окружения (две базы) в один контейнер или одну папку документов: очистка сирот каждого worker удалит документы другого. У каждого окружения своя учётная запись хранилища; локально e2e-база пишет в `.local/documents-e2e`, разработка — в `.local/documents`.
