# Vardahei CRM v2 — notes for Claude

CRM for an IT company (Microsoft / Atera / PowerOffice partner). Specs live in `docs/` (Russian); code, comments and commit messages are in English. UI strings go through i18n (`web/src/i18n/locales/{nb,nn,en}.json` — Bokmål, Nynorsk, English; Russian was dropped; keep keys in sync, a vitest test fails otherwise). The product is spelled **Parasoll** in the interface. Only the chosen language is downloaded, so there is no fallback language at runtime.

**State (05.10.2026):** DEV-00…DEV-22 of the audit package are implemented and checked locally (`code_verified`, synthetic data, mocks); DEV-23 (release readiness) is open and external gates EXT-01…EXT-11 are not passed. The system is **not released and not accepted** — see `docs/08-roadmap.md` § 0 and `docs/claude-opus/GO_LIVE.md`. Never write "accepted", "production-ready" or "paid" for anything a local run or a mock proved.

## UI rules
- Visual system (Hearth reference, docs/ux/UX-CONCEPT.md §8): component shapes live in `web/src/app/hearthControls.ts` and `hearthSurfaces.ts` (Fluent `customStyleHooks_unstable`, combined in `hearthStyles.ts`), tones in `--h-*` variables (`web/src/styles.css`, `app/hearth.ts`); pages use plain Fluent components plus `Panel`, `KpiTile`/`StatTile`, `FactGrid`, `PageHeader` (its `back` is the 44 px back button), `EmptyState`, and `Toolbar`/`FilterField`/`FilterChips` for list filters (no labels shown above filter controls). Motion is in `app/motion.ts` (entrances, counters, the menu pill, magnetic buttons, `h-stagger` lists); every animation stops under reduced motion, and audits run with reducedMotion 'reduce'. Import `Dialog` from `shared/components/Dialog` (it carries the dialog motion; lint forbids Fluent's directly). While a modal locks the page scroll, `app/scrollLock.ts` swaps Fluent's empty scrollbar gutter for padding, so the backdrop reaches the window edge, and keeps body from becoming a scroll container, so sticky parts stay put; the window then grows by the hidden scrollbar, so a fixed layer that spans it adds `var(--h-locked-scrollbar, 0px)` on its right (glow, tab bar, toaster). Tint badges are retoned to AA pairs in both themes (axe-checked 20.10.2026), so `appearance="tint"` is fine; keep text in `--h-*-t`/token colours, never a bare `--h-faint` below 4.5:1. Override Fluent with longhand properties (`paddingLeft`, not `paddingInline`): Griffel does not merge logical shorthands with Fluent's longhands; a focus style needs `':focus-within:focus-within'` to beat Fluent's `:active,:focus-within`. The shell's first download is budgeted (`scripts/bundle-budget.mjs`, ≤ 300 KB gzip): load rarely shown overlays (search, drawer, toaster) lazily, and shell modules take their icons from `web/src/app/shellIcons.ts` (one icon family per module; the package index drags every page's icons into the first download, lint enforces it).
- Behaviour rules (docs/ux/UX-2026.md): one primary button per layout (the top bar's New menu is secondary); a status line is green only for a complete read and lists its gaps in the same box, details behind a disclosure; a fact is said once (an alert's urgency is its severity badge); lists show ages with `formatRelative` in `<time dateTime title>` and record views pass `exact`; empty side cards use `EmptyState compact`; empty record fields are named in one "Not filled in" line, not a column of dashes. An irreversible action (close a month or an hour bank, delete a project, phase, task or timesheet entry) asks in `shared/components/ConfirmDialog` that names the record and the effect, never in one click or the browser's `confirm`. A page closed by permissions renders `features/errors/ForbiddenPage` ("No access", no retry), while a record out of scope stays "not found" (DEV-09). Field borders use `--h-field-edge` (≥ 3:1 in both themes). Hours typed by people go through `features/time/hours.ts` (`1,5`, `1:30`, `45 min`) and the dialog echoes the stored value. Lists that show facts about many records read them in one batch per page (customer facts, alert task links), never per row. Interface words follow the glossary in docs/ux/UX-CONCEPT.md §7: the customer tab and menu area are "Drift" (EN "Operations"), alerts are "Driftsvarsler"/"Driftsvarsel" (the bell keeps "Varsler"), machines are devices ("Enheter"/"Einingar"); a vendor name appears only as the source label.
- The e2e database is shared between runs, so assertions narrow the list first (search box, marker in the row) instead of relying on `.first()` or on totals. My tasks of the shared sign-in users fill up with open tasks without a due date (they sort first), so a test finds its own task row with `showInMyTasks` (`web/e2e/support.ts`) and closes the tasks it leaves behind.
- Specs run in parallel and share one development user per role, so a test that changes the user's own settings (the language) signs in as a named user of its own: `signIn(page, role, url, 'Language')` is `/bff/dev-login?…&user=Language`, "Dev Language" (letters only, development sign-in only).
- E2E tests claim a billing month by creating the run (`reserveBillingRun` in `web/e2e/support.ts`; the open-period unique index makes it atomic) and give test contracts an end date in that month, so no other test's run bills them. crm-web runs over HTTPS in e2e because WebKit drops Secure cookies on http.
- A page that waits for the worker (an exporting billing run) sets `refetchInterval` on the query while that state lasts instead of leaving the user with a stale screen.

## Architecture rules (enforced by tests/Crm.ArchitectureTests unless noted)

### Modules, API and conventions
- Modular monolith. A module references another module only via its `*.Contracts` project or domain events; no cross-schema foreign keys. The Contracts module's public project is `Crm.Contracts.Contracts` (namespace clash is expected).
- Reverse questions go through interfaces in the asking module's contracts, implemented elsewhere: e.g. Catalog asks `IEnumerable<IProductUsage>` whether a product may be deleted; Contracts implements it.
- Core modules never reference `Crm.Integrations.*`; integrations call modules through contracts.
- One schema and one `ModuleDbContext` per module; every context must declare `public const string SchemaName`. New contexts are registered with `AddModuleDbContext<T>()` — registration order is migration order (Audit first).
- No MediatR/AutoMapper (commercial licences): plain handler classes registered by `AddModuleServices`.
- Global search: modules contribute `ISearchProvider` (SharedKernel); the host filters providers by the caller's permission.
- Every `/api` endpoint needs `.RequirePermission(...)`; permissions are mapped from Entra App Roles only in `Crm.Authorization/Permissions.cs`. An integration test fails for unprotected endpoints.
- Writes: `If-Match` required (428 otherwise), ETags come from the tracked entity's `RowVersion` (no-tracking queries cannot produce ETags). State-changing requests need the `X-CSRF: 1` header.
- A DTO property that carries an ETag is named `Etag`, not `ETag`: the web JSON policy turns `ETag` into `eTag`, and the SPA reads `etag` from the body when it sends `If-Match`. An integration test pins the name.
- IDs: `SequentialId.New()` (SQL Server-ordered GUIDs), not UUID v7.
- A child entity whose id comes from the domain (`SequentialId`) needs `HasKey(x => x.Id)` and `ValueGeneratedNever()`; without it EF treats a new child with an id as an existing row, marks it `Modified` and SaveChanges fails with a concurrency conflict. `ConfigureAuditable()` already does this, plain `Entity` children do not.
- Money shown to roles without `finance.read` / `finance.cost.read` is removed server-side with `[SensitiveData]` on response DTOs; handlers must also not let those roles overwrite fields they cannot see.
- "Today" for business dates is Europe/Oslo (`OsloClock.Today`); `DateOnly` is used for contract, price list and hour bank dates.
- Domain events may carry enums: both sides of the outbox (the interceptor and `OutboxProcessor`) serialize with `JsonStringEnumConverter`.
- A list endpoint returns `PagedResult` (`items`, `nextCursor`, `totalCount` of the whole filter) with keyset paging: the last sort key is `Id`, the cursor carries every sort value and the continuation `Where` mirrors the `OrderBy` (an enum stored as a string sorts through a `CASE` rank). Money and counts over a list are SQL aggregates of the same filter and scope, computed before the page. Never `Take(n)` a user-facing list or a background scan silently: a top-N widget says "N of M", a scan narrows in SQL (DEV-12). The SPA reads lists through `usePagedList` and ends them with `ListFooter`.
- Activities hang off an organization, optionally also a deal or a contract — there is no generic "regarding" pointer; an `ActivityLogged` event is what refreshes a deal's last-activity date.
- Integration tests share one assembly fixture and run classes in parallel, so anything global (a paused integration) needs its classes in one `[Collection]` with `DisableParallelization`.

### Persistence, audit, rights and releases
- Audit rows and outbox messages are written by `AuditingInterceptor` in the same transaction; domain event handlers must be idempotent. A request with no aggregate to raise an event adds `OutboxMessage.For(event, …)` itself in the same `SaveChanges`.
- Outbox delivery (DEV-07, ADR-016): messages have explicit states (`Pending/Processing/Processed/DeadLetter/Quarantined`), a lease with an owner token (every later change is compare-and-set on `LeaseOwner`) and per-handler receipts (`InboxReceipts`) committed in the handler's own transaction. **A handler changes one module only** (`MessageHandlingContext` throws otherwise) and opens no transaction of its own; another module reacts with its own handler. Handlers make no external calls: Teams cards go to `notifications.ChannelPosts` (`ChannelPostJob`), external writes to `OutboundOperations`. A handler that applies a reversible change (merge/undo, phase completed/reopened) checks the source's current state, because retries and replays deliver out of order. Replay is `POST /api/v1/integrations/outbox/replay` (≤ 100, reason, `expected`), applied by the worker; tests that simulate a crash before the acknowledgement set `Status = Processing` with an expired lease, not just `ProcessedAt = null`.
- Database rights (DEV-04, ADR-014, runbook 08): crm-web and crm-worker run as their own identities in roles `crm_web`/`crm_worker` (members of `crm_runtime`) — no `db_datawriter`, no DDL, audit insert-only, no deleting financial records. The migrator re-applies grants after every migration (`DatabasePermissions` + each module's `IDatabasePermissionRules`); a table whose rows must never be deleted or rewritten gets its deny there. A DDL trigger refuses broad fixed roles for app identities (so a rollback cannot widen rights).
- Approved billing data (runs, bases, lines, approvals, charges, export attempts) and `audit.AuditEntries` are guarded by SQL triggers; such tables must be mapped with `HasTrigger` (else EF uses OUTPUT without INTO) and a migration carries its trigger SQL verbatim, not a reference to a constant that may change.
- Integration tests run as a SQL login in `crm_worker` only; a test that plays the database administrator (restore, data from before a migration, role checks) uses `factory.AdminSqlAsync`/`AdminSqlWithoutBillingTriggersAsync` and belongs to `DatabaseAdministrationCollection`.
- Audit retention only through `audit.ApplyRetention` under `crm_privacy`: dry run unless an approved policy exists (DEC-03); it redacts the personal part and never touches the audit of financial modules (`billing`, `contracts`, `time`, `sales`, `projects`, `catalog`, `licensing`). The audit hash chain (`audit-integrity` job) is anchored in the log workspace, not in the database alone.
- Releases (DEV-05, ADR-015): CI on main → `release.yml` builds the images once and deploys their digests to test; prod only through `promote.yml`, which imports the same digests (never rebuilds). A new CI job must join the `release` job's `needs` (an architecture test enforces it); actions are pinned by commit SHA; dispatch inputs reach scripts only through `env`. Migrations are expand-only (architecture test); a migration that creates a trigger is registered in `tools/release/schema-breaks.json` (DEV-04's billing triggers are a break: older releases cannot write with them).
- Environment-bound settings are fixed per environment in `infra/env/*.bicepparam` and checked by the app against `Deployment:Environment` at startup (PowerOffice: test → Demo, prod → Production).

### Sessions, security and personal data
- Users are deactivated by the Entra sync; `ActiveUserMiddleware` rejects their API calls (`401 USER_INACTIVE`).
- Parasol access (ADR-030): every employee holds `Crm.Admin` (all permissions) through the Entra group "Parasoll – full tilgang" (without Entra ID P1: assigned to each user directly). Keep every permission check in code anyway, and never word a refusal or a layout by the user's role in the UI; My day layout is the user's own choice.
- Sessions and roles are server-side (DEV-10, ADR-019): the cookie names an `identity.UserSessions` row, and `OnValidatePrincipal` replaces its role claims with the roles the directory confirmed (`entra-role-sync` every 2 min, or the sign-in token), cached per replica for 30 s. A change allowed only through `Permissions.Privileged` permissions, or any endpoint marked `.ExportsData()`, needs a confirmation younger than `Auth:PrivilegedFreshness` (5 min), else `403 AUTH_REVERIFY_REQUIRED` — mark every new bulk export with `.ExportsData()`. The role sync writes a user only when the roles change (audited) and records the reading once per tenant (`DirectoryRoleConfirmations`); a `SyncRunner` job that runs every few minutes passes `quietFor`. The hourly refresh-token check ends the session when Entra refuses the account and postpones itself 5 min when Entra cannot be reached. Production refuses to start without the shared Data Protection key ring.
- Security (DEV-21, ASVS 5.0.0 L2 self-assessment, `docs/claude-opus/evidence/DEV-21/`, ADR-024/025): a post-sign-in address goes through `ReturnUrl.Safe` (single leading slash, every decoded form, no control chars/backslash/non-ASCII) and nowhere else; Production refuses to start with `AllowedHosts` `*` (Bicep names the hosts) and trusts `X-Forwarded-*` only from `Forwarded:KnownNetworks` (apps subnet; unset = private ranges), `X-Forwarded-Host` only for allowed hosts. A privileged action needs fresh roles AND `crm_auth_time` (id_token `auth_time`, optional claim registered in the app registration, else privileged actions stay closed; `Auth:RequiredAcr` empty = strength is Conditional Access/EXT-02); `AUTH_REVERIFY_REQUIRED` is answered by `/bff/login?reverify=1` (`prompt=login`, `max_age`, the answer re-checked). Every `.ExportsData()` endpoint also needs `.RequireRateLimiting(Export)` (Migration for run-report pages): a test enforces it. CSV imports read the body through `CsvUpload` (text/csv|text/plain else 415, `Imports:MaxRequestBytes` 10 MB else 413, `CsvTable.MaxImportRows` cap) and CSV/Excel exports write text through `CsvCell`. Every `/api` endpoint with a JSON body has `.Validate<T>()` with a registered validator or an allowlist entry with a reason (`RequestHardeningTests`); a regex validator ends in `\z`, not `$`. Graph nextLink/deltaLink and the token go only to the configured Graph origin (`GraphLinks`), provider clients never follow redirects, integration URLs are https (Teams webhooks also on an allowed host). A role that cannot see a money field (`[SensitiveData]`) never overwrites it: keep the stored value in the handler. OpenAPI is off unless `OpenApi:Enabled` (then `integrations.manage` only); no source maps; `appsettings.Development.json` is not published. Refused requests, sign-ins, and report/BI reads leave `Crm.Security` log lines or audit rows with ids and route templates only — never a query string, token or amount (new log sinks and crypto uses go into ADR-025/ADR-024).
- Record scope (DEV-09, ADR-018): a permission says whether a role sees a kind of record, `IRecordScope` which of its records. Roles without `sales.quotes.all` see the quotes whose current version they own; roles without `projects.all` (technicians) the projects they manage, are on the team of (`projects.ProjectMembers`) or have a task in. The owning module applies the scope in every query — lists before filters, the single load-by-id (out of scope = 404 like a missing id), documents, contract methods — so a new path to quotes or projects (search provider, custom fields, history mapping, report) must go through it. Owners change only by transfer (`POST /quotes/{id}/transfer`, audited); an omitted `ownerId` keeps the owner. `Authorization:RecordScope` is Restricted by default; Open is a per-environment exception (Bicep `recordScope`, runbook 11).

### Personal data (Privacy module)
- Personal data of customers' people goes through the Privacy module (DEV-11, ADR-020):
  - a module that stores data about a contact or a lead implements `IPersonalDataContributor` (export, plan, erase, reapply) and is listed in docs/04 §9;
  - erasure pseudonymizes rows so references stay, it never cascades; audit history and stored quote documents are hidden at once and cleared only by the `crm_privacy` operator procedures;
  - domain events about people carry ids only;
  - retention is DryRun until EXT-07: periods come only from `privacy.RetentionPolicies`, which the DBA writes;
  - deletion manifests live in the document store under the installation's folder and are replayed after a restore, with the API answering 503 meanwhile.

### Integrations
- Provider credentials (PowerOffice, Atera, Partner Center, Teams webhooks) reach crm-worker only. `IIntegrationAdapter.IsEnabled` follows the `Enabled` switch, so stored-data features work on crm-web; code that calls a provider checks `IsConfigured` and runs in the worker. A provider call the UI asks for is queued (the connection test: a `connection-test` sync run + outbox event, polled by the page).
- External systems plug in as `IIntegrationAdapter` + sync jobs + `IOutboundHandler`s (see `Crm.Integrations.PowerOffice`). Adapters store what they read via `ExternalRecordStore` (hash-based change detection) and link via `ExternalLinkService`; outbound handlers must compare with the live external record and send only CRM-owned fields. Writes to external systems are behind `WriteEnabled` flags.
- Integration safety (DEV-19): any create toward a provider is journalled and looks up our key first; only reads are retried on 5xx/timeouts (writes on 429 only). A falling invoice balance is stored as `BalanceDecrease` ("observed decrease", dated by the sync), `CreditNote` or a flagged `BalanceIncrease`; `Payment`/`WriteOff` stay unused until a ledger proves them, so nothing says "paid". Stale licence/device readings (`Billing:StaleQuantityDays`), live-only devices and an incomplete work-hours import add `BIL_STALE_QUANTITY`/`BIL_NO_DEVICE_SNAPSHOT`/`BIL_INCOMPLETE_HOURS` and the `billing:estimated` signal; they never block a basis.
- Every provider (Atera now; Huntress and CloudAlly from M41/M42) integrates directly as `src/Integrations/Crm.Integrations.*`; the separate integration service retired in M38 (`docs/migration/M38-OPERATIONS-IN-CRM.md`) does not come back, and neither do personal provider tokens or JSON identity imports.
- Vendor actions (M39, `docs/migration/M39-VENDOR-ACTIONS-TICKETS.md`): every change a person asks of a vendor is an `IVendorActionHandler` in `Crm.Integrations.Core/Actions` with its vendor's `IVendorActionGate`, never a direct client call from an endpoint. The preview is built from saved data only and signed; the command saves the `VendorActions` row with its `action:{kind}` outbound operation in one transaction; the worker re-reads the switches (`WriteEnabled`, `DryRun`, `WriteAllowedCustomerIds`, `EnabledActions`), the maintenance gate and the live record before sending. A non-repeatable action without a clear answer becomes `Uncertain` and is never sent again; a person settles it on `/connections`. Codes are `VND_*` (`ACT_*` is Activities'), audit carries ids only, and a ticket action's words are personal data (`IntegrationPrivacy.cs`).
- Alerts (M38): `service.Alerts` keep a stable id per `System` + `ExternalId` with `State` Open/Acknowledged/Resolved and `Kind` Monitoring/Security/Backup. A read reports through `IServiceApi.ApplyAlertSnapshotAsync`: listed alerts become or stay open, and a stored open or acknowledged alert is resolved only when a **complete** read no longer lists it; an incomplete or failed read changes nothing, and alerts of customers without a link are never touched, so a reader fails as a whole on a page it cannot read or an alert without an id. An alert gets a device only when exactly one current device of the customer carries its name, and a link only from a configured template (`AlertUrlTemplate`), never a guessed provider address.
- Integrations record runs and incremental cursors through `SyncRunner` (`integration` schema); recurring jobs are registered in `Crm.Worker/Program.cs`. External calls in tests go to WireMock (`CrmWebFactory.Brreg`, `.Graph`).
- CSV that comes from a partner or a distributor is read with `Crm.SharedKernel/Text/CsvTable`: delimiter sniffing, quotes, header aliases (case, spaces, underscores, Norwegian spellings), Norwegian and English decimals and dates. Unknown columns are reported, never rejected, and every import has a `?dryRun=true` preview that counts exactly the way the real import does.
- Money that Microsoft charged the partner is cost data: the reconciliation and the NCE price-sheet import sit behind `finance.cost.read`, not behind the module's own write permission. A price sheet is applied only to a **draft** price list — an active one carries prices contracts already quote.
- An external cost or usage line gets a deterministic key (`{source}:{invoice}:{subscription}:{offer}:{period}` for billed lines, `(organization, date, sku)` for licence snapshots) so a re-run of the job and a re-import of the same file are both no-ops.
- CSP subscriptions are a read-only mirror (Partner Center jobs or a distributor CSV). `POST /api/v1/licensing/import?dryRun=true` previews what a file would change without writing; the preview must count the same way the real import does.
- Entities compared against an external source have a `Signature()` used for change detection: format decimals with `"0.####"` and dates with `"yyyy-MM-dd"` under `CultureInfo.InvariantCulture`, otherwise a database round-trip makes every sync look like a change.
- An integration can be paused at runtime (`integration.IntegrationSwitches`): `SyncRunner` records a `Skipped` run with the reason instead of working, and the outbound processor leaves that system's queue alone. Configuration flags (`Integrations:*:Enabled`) still exist for turning a system off for good — the pause is for incidents, where a new revision is too slow.
- Delegated Microsoft 365 (calendar, mailbox) runs on the signed-in user's token: the integration asks `IDelegatedTokenSource`, which only `Crm.Web` implements (from the BFF token cache). `IsAvailable` answers for configuration, a missing token throws `UserNotConnectedException`, and every surface says "not connected" instead of failing — the development sign-in never has a token.
- What lives in Microsoft 365 stays there: the mail tab reads the mailbox live and saving a message stores subject, sender, time and a link but never the body; SharePoint keeps the files and the CRM only stores the folder id in `ExternalLink` (SEC-GDPR-06/06b).
- A meeting pushed to Outlook carries its activity id in the open extension `no.vardahei.crm`, so an event read back through `calendarView` finds its activity without touching the subject the customer sees.

### Billing, contracts, time, sales and reporting
- Time entries are split into allocations (covered / hour bank / rate) instead of separate entries; hour bank movements are keyed by entry id + approval number so a re-approval never books twice.
- Parasol M24 / ADR-027: Time approve/withdraw/import bank effects share one explicit Time-owned nonretrying SQL transaction via `TimeBankTransaction`; each module retains its own context/API/audit/outbox. Same CRM database and SQL identity only; active inbox handlers, arbitrary external transaction owners and outer retry callbacks must refuse. Order source fences → sorted M23 month locks → global financial lock → rows → bank work → owner commit. Billing terms read own writes. Historical receipt mismatches require Finance review; no random fresh keys or automatic ledger rewrite. Export/invoiced is still a separate boundary.
- Billing invariants (DEV-01…04, ADR-011/012/013; implemented and tested locally, Finance acceptance of disputed history is EXT-01): approved bases are immutable, manual corrections survive a re-collect once, repeated export is safe. The run export key `{period}-{organizationId}-{runId}` is only the PowerOffice external reference of one basis; it does **not** prevent economic duplication across runs — that is the job of the charge register `billing.Charges` (one effective obligation per charge key). Approvals bind to one revision of the run content and need two different people above the threshold. Do not weaken these when touching billing.
- Work that has to reach the next billing run waits in `billing.PendingCharges` and is closed only when a basis is actually exported, so a cancelled or re-collected run neither loses nor duplicates it.
- A quote is stored one row per version: versions share `Number` and `RootId`, only a draft is editable. Releasing a version (submit/approve → Ready) freezes its document (DEV-08, ADR-017): `sales.QuoteDocuments` keeps a snapshot of every printed field and the PDF goes to `IDocumentStore` (a private persistent POSIX volume on Hostinger, ADR-026) under a key that is never reused, with its SHA-256. Downloads and e-mail attachments read that stored object and check the hash; nothing is re-rendered from changing data. A document stays `Preparing` (no download, no send) until stored — `QuoteDocumentJob` retries and adopts an object stored before a crash. Ready documents never change and are never deleted (trigger + DENY). Versions released before DEV-08 get an Issued document if never sent, otherwise a Reconstructed copy labelled on every page. The renderer is `Crm.SharedKernel/Documents/PdfBuilder` (core Helvetica, WinAnsi, nb/en); bump `QuotePdf.RendererVersion` when its output changes — stored documents stay as they were. Every field prints whole (wrapped in its column, never cut with an ellipsis; only the template footer gives way to the page number). `FileSystemDocumentStore` uses create-only hard links and file/directory sync across processes; production requires an existing absolute `Documents:RootPath` and `Documents:VolumeId` matching `.parasol-volume`. Storage tests cover independent processes, interrupted writers, volume identity, and the real SQL release/download/mail/restore journey (`VpsDocumentStoreTests`). Follow runbook 16 for VPS provisioning, migration and recovery.
- A project owns the plan, never the hours: a time entry carries `ProjectId` and the plan-against-actual numbers come from `ITimeTrackingApi.GetProjectHoursAsync`, so the timesheet, the project and the invoice can never disagree. A completed phase with a fee reaches billing through `billing.PendingCharges`, like an accepted quote.
- A contract line that is in force for only part of a billed period is prorated by days (`BillingSchedule.Prorate`): the unit price carries the fraction, the quantity stays what the customer has, and the description shows the window and `15/30`. This is also how a mid-period change works, so `GetBillableLinesAsync` returns every version of a series that overlaps the period, not only the newest one.
- Indexation only touches contract lines with their own price; a line that follows the price list is indexed when the price list is (BR-CON-06). Each indexed line gets a new version from the effective date, exactly like a manual revision.
- An organization billed through its group parent has no basis of its own: the collector moves its lines onto the parent's basis, prefixed with the subsidiary's name, and drops a basis the subsidiary had from an earlier collect (BR-BIL-12).
- SLA time runs only inside the agreement's support window and never on a weekend or a Norwegian public holiday: `Crm.SharedKernel/Time/BusinessTime` counts it and `NorwegianHolidays` computes the movable days from Easter. The same helper decides what counts as after-hours work in the tariff engine.
- A notification stores its kind and parameters, never a finished sentence: the interface renders it through i18n and the e-mail digest renders the same notice in the reader's language (`NotificationTexts`). Enqueueing is idempotent through a dedupe key that carries the date, so a repeated scan adds nothing.
- Reporting owns no schema. `Crm.Reports` composes the dashboard and the BI datasets from other modules' contracts; historical values are kept as snapshot objects in the document store (ADR-022), not re-read from live data. A reporting schema would need its own ADR.
- Power BI (DEV-14, ADR-022): the cookie mart `/api/v1/reports/mart` is the legacy path; Power BI Service reads `/api/v1/bi/v1`, which takes only an Entra bearer token on its own scheme (`BiBearer`) and policy (`bi`: tenant, `Bi:AllowedClients`, app role `Crm.Bi.Read`/`Crm.Bi.Cost`). Never add the bearer scheme as a default or to another route, and never expose the operational database to solve refresh. A BI dataset is typed, ordered by its key columns, versioned (`schemaVersion`) and carries `asOf`; it holds no record-scoped data (quotes, projects). Historical figures come from `BiSnapshotService` (create-only objects in the document store, `Captured` or `Reconstructed`), not from re-reading live data. A column called "paid" needs payment semantics the CRM does not have: say `outstanding`. A new dataset or a changed definition: update `BiService.Datasets`, the glossary and runbook 14 together.
- Custom fields (`customfields`) store definitions and values keyed by `(entity type, entity id)` with no foreign keys, so no module depends on them: a card asks the custom-fields API by its own id and renders whatever comes back. Defining fields is an admin right; answering them follows the customer permissions.

- Parasol M25 / ADR-028: Billing approval/send validates exact active Time allocation IDs and source organization under a short nonretrying Time read lease held through local Billing save. Never hold it during provider HTTP. Immutable nonexcluded Approved/Exported/Failed/ReconciliationRequired time lines fence all Time financial writers under M23 admission; source changes preserve values and flag review. Draft/Cancelled/Exclusion do not freeze work. Dedicated `ITimeBillingReader` avoids a module/DI cycle. Inbox finalization validates the exported revision, and `BillableTime.Invoiced` is per allocation so excluded Rate survives exported Info. Unknown history requires Finance review; no automatic rewrite. Delayed-event SQL tests use the existing nonparallel collection because other classes drain the shared outbox.

### Operations, health and recovery
- Monitoring (DEV-17, ADR-023): `SyncSuccesses` advances only on a complete successful sync, including quiet runs; connection tests never prove freshness. Module diagnostics implement `IOperationalSignalSource` in SharedKernel, emit counts and explicit recovery zeros, and declare the permission needed to see them. Never put amounts, customer identifiers or raw exception/provider text in metric labels or shared failure logs. Triage uses If-Match and audit; retry/replay confirms concrete IDs and a reason. Actual alert recipients and delivery remain EXT-01 (runbook 15).
- `/health/integrations` is for monitoring only and never part of readiness: a sulking external system must not take the CRM out of the load balancer.
- Health (DEV-06): `/health/live` is the process (plus, in crm-worker, the in-memory outbox loop rounds — never the database); `/health/ready` is `DatabaseReadinessCheck` (`SELECT 1` with a short connect timeout, pending migrations rechecked every 5 min); probes answer with the status word only. Worker components store heartbeats (`IWorkerHeartbeat` → `integration.WorkerHeartbeats`) read by `/health/details` (admins). The outbox loop is registered with `AddOutboxProcessing()`, not `AddHostedService<OutboxProcessor>()`.
- Read-only maintenance (DEV-13, ADR-021) lives in the document store (`operations/maintenance/`), not in the business database. `IMaintenanceGate.CurrentAsync` (cached ≤ 5 s) gates requests and EF writes; `FreshAsync` is read before every external send and fails closed. Any new external effect starts with `IExternalEffectJournal.BeginAsync` (it re-reads the switch and refuses during maintenance) and completes with `Sent`/`Failed`/`Skipped`; journal entries carry ids only. A write that must happen during maintenance opens `MaintenanceScope.AllowWrites(...)` around exactly that work (bookkeeping of work already under way, the operator's reconciliation); an endpoint that must keep working is marked `.AllowedInMaintenance()`. Both EF interceptors (SaveChanges and `ExecuteUpdate/Delete/ExecuteSql`) enforce it, so `ExecuteUpdate` bookkeeping needs a scope too. Only holders of `operations.maintenance` sign in during maintenance (`ProvisionUserAsync` decides; others get `/?maintenance=signin`), and the Entra user and role syncs keep running — the operator's privileged actions need a fresh role confirmation.
- Maintenance in integration tests: never switch the shared factory. Use a host of the test's own with a `SplitDocumentStore` (its switch in a private store, everything else shared), and provision test users before switching — provisioning is a write.
- A restore is done with `tools/ops/restore.py` (names from deployment outputs, dry run by default, renames only by a confirmed `switch`, never deletes) and reconciled with `POST /api/v1/operations/restore/reconcile` while read-only (runbook 03). Each module that sends something has an `IRestoreParticipant`.
- Migration from the old systems (DEV-20, runbook 16) is an ordinary import endpoint with `?dryRun=true` (`POST /api/v1/customers/organizations/import`, permission `customers.delete`, own rate limit `migration`), not a script with database access: same permissions, same duplicate rules (BR-CUS-06), same audit trail. The CRM is the master: `Organization.FillGaps`/`Contact.FillGaps` fill only empty fields, a different value in the file is a field-level `Conflict` (names, never values) and is not applied; an event is raised only for a real change. Every call is an `ImportRun` (customers schema: source SHA-256, mapping version, repeat key, one outcome per row, batch marker `ImportRunEntities` = the compensation list; no names or e-mail addresses are stored, outcomes and markers are insert-only for the application). A real run saves in chunks (`Customers:MigrationChunkSize`), a failed chunk makes the run `Partial` and the same file resumes after `LastCommittedLine`; a completed file returns its stored result. Rejections carry codes (`INVALID_ORGNR`, `DUPLICATE_IN_FILE`, ...), messages are `Row N: CODE`. `CsvTable` reads quoted multi-line values and keeps physical line numbers.

- Parasol M26 / ADR-029: `GET time/entries/{id}/financial-review` is read-only and requires all five Time/Finance/Contracts/Billing/Customers read permissions before lookup. Resolve customer names before the Time month/row lease; read related bank/Billing facts through public contracts. Never SaveChanges/commit, create a period or repair history in this GET. Include closed/deleted references, mask foreign bank names and compare exact allocation revisions. `reviewOnly` filters saved notes before totals/paging; it is not a global discrepancy scanner. DTO GUID validation must support existing SQL-sortable SequentialId values; keep the pure parser free of UI imports.

- Task ticket refresh (Parasol M28, kept in M38): a successful Task ticket link/unlink changes the Activity rowversion. Preserve the open ticket/time dialog, then re-read the complete scoped parent Activity after closing. Keep the original launcher until focus has returned; only then let the parent replace its row and move focus to a stable existing control. Never copy only the association ETag into stale Activity fields or auto-retry complete/reopen. Personal/selected/timeline regressions live in `TaskTicketRefresh.test.tsx`.
